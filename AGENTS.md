# Workloom

Workloom is the provisional name for a team task tracker. This monorepo holds a React/TypeScript client and Node.js/TypeScript backend. The repository contains application code: P0 (React → Fastify → PostgreSQL with a synthetic development identity), bounded P1a (projects, sections, statuses, tags, workspace-visible tasks with shared work-package estimates), bounded P1b (nine typed project-scoped custom fields, stable option IDs, shared project-column settings, value history and custom-field locks), bounded P2a (weekly periods, personal commitments/allocations, source-fresh personal/project freezes, period work revisions and pinned weekly plan/fact reports), and bounded P2b (project work-category binding, immutable category snapshots and explicit recategorization, pinned work-type reports, explicit-week personal plan/fact entry from the task table). Accepted bounded P3a adds one-off meetings, explicit personal-plan preview/apply, atomic attendance and immutable occurrence work revisions; exact functional, browser and visual evidence is recorded separately in the journal. Accepted bounded P3b adds finite recurring meetings bound to explicit periods, stable occurrence headers, shared DST resolution, same-transaction census/materialization before freezes, stored generation grants, durable worker receipts and a local pg-boss outbox/worker lifecycle. Accepted bounded P4a adds same-workspace cross-project finish-to-start dependencies, global cycle checks under the workspace barrier, authoritative warn/status-only-enforce blocking, a bounded basic graph and personal full-set layout preferences. Accepted bounded P4b adds nullable date-only task starts, shared final-range validation, source-fresh atomic schedule preview/apply, a bounded manual-date Gantt and explicit immutable baseline-date overlays. Accepted bounded P5a adds UTF-8 CSV staging, explicit existing-reference/scalar mapping, full source-fresh preview, atomic create-only import and unchanged-source skip with immutable external IDs and independent target revision vectors. Full Asana migration, JSON/live sync, imported original estimates or weekly facts, source private-ACL migration and complete MCP/production integration remain separate future gates. Full P1 (private ACLs, shared Auth, saved views, bulk edits and complete built-in-field history), full P2 (close/corrections, full-package completion accuracy, late estimate acceptance, split/replace/transfer/carryover commands and daily work logs), arbitrary recurrence/invitations/infinite calendar, Gantt date pointer drag/resize, automatic scheduling, historical dependency topology, external MCP adapters and deployment are not done. The exact P2a/P2b/P3a/P3b/P4a/P4b/P5a catalogs and limits live in `docs/13-p2a-contract.md`, `docs/14-p2b-contract.md`, `docs/15-p3a-contract.md`, `docs/16-p3b-contract.md` and `docs/17-p4-contract.md` and `docs/18-p4b-contract.md` and `docs/19-p5-import-contract.md`; acceptance evidence stays in the journal, not in the implementation status paragraph. Use `README.md` for setup. `docs/11-implementation-progress.md` and `docs/12-active-run.md` preserve historical verification; current daily-UX evidence and runtime boundaries live in `docs/24-current-ux-run.md` and `docs/25-ux-verification.md`.

Accepted bounded P5b adds local stdio MCP with nine tools: seven authorized reads and explicit task create/update using current self-owned hash-only credentials. Every discovery/read uses current authorization; every task write rechecks the credential after the workspace barrier before any receipt. The core write option defaults to false; the normal local API explicitly enables the accepted two task tools. Limits are 100 own credential records, 500 active projects, 1000 active memberships, 200 field definitions/values and a 2 MiB serialized bridge result, with controlled overflow. Exact scopes, fixed hash encoding, protocol and revocation-race gates are in [docs20](docs/20-p5b-mcp-contract.md); dated functional/browser/visual evidence is in the journal. Real Auth, private ACL, remote MCP/OAuth, report/time/recurrence tools and production remain outside this local synthetic slice.

The bounded local UX includes JSON-only locale discovery with English catalogs, My tasks, explicit task editing, retained task/hour/field drafts, week/person context, literal discussion, pinned report views, personal column order/visibility, section/assignee grouping, applied-filter summaries and a loaded-task status board. Personal columns do not save filters/sorts/widths, named views or permissions; shared project defaults remain separate. Drafts stay in memory and do not survive confirmed departure/reload. Exact contracts are indexed in [docs/README](docs/README.md); current acceptance and preserved failures live in [docs25](docs/25-ux-verification.md), with the phase ledger in [docs24](docs/24-current-ux-run.md). ## Working boundaries

- Keep client code in `apps/web`, server adapters in `apps/api`, jobs in `apps/worker`, shared contracts in `packages/contracts`, domain commands in `packages/domain`, persistence in `packages/db`, and shared UI in `packages/ui`.
- Run all commands with this repository as the explicit working directory. Commands described in planning documents are intended future interfaces until implemented; do not claim they already run.
- Preserve other contributors' uncommitted changes and stay within assigned files.
- Early local versions may use a development identity adapter without login. Keep workspace/actor context and permission checks in domain commands. The no-login mode is for local development with synthetic data, not a deployable public authentication bypass.
- UI, HTTP, MCP, imports and background jobs use the same domain commands and access rules. Baselines and confirmed history are corrected by revision, not silently overwritten.
- Entity IDs are UUIDs; the shared `idSchema` in `packages/contracts` canonicalizes them to lowercase, and domain code compares IDs case-insensitively.
- Custom-field types are immutable. Null, zero, false and an absent value row are distinct. Keep definition, value and project-column-setting revisions independent. Disabling value history never deletes existing immutable snapshots; audit/outbox for value writes contain metadata, not hidden old/new values. The P1b manual custom-field lock is distinct from P2a baseline locks on selected task/field and work-package identities, including absent/null values.
- Every new task/field/planning mutation must declare an exhaustive typed intent and run the mandatory planning guard after current authorization/idempotent replay and before its handler. Overdue freeze saves old sources under the shared workspace barrier. A protected edit commits only the freeze and tagged idempotent rejection; unwrap FIELD_LOCKED after the transaction commits. Unexpected errors roll back everything; never catch a late handler error and commit partial writes.
- Preserve immutable personal/project snapshots and first package-freeze observations. An unknown first whole-package estimate stays original-unknown even if protectEstimate was false and a current estimate is filled later; explicit late acceptance is future work. New post-freeze work is server-classified added/unplanned, never client-claimed original.
- Weekly reports use pinned baseline/worklog revisions and authoritative server summaries/by-person groups. Do not replace missing/void with zero, multiply work logs through tags/participants/children, or derive full totals from loaded row pages. Manual-period facts have no invented daily precision.
- Work categories use stable project field/option IDs and immutable first-fact snapshots. Hours-only corrections copy the existing category; explicit recategorization requires a reason and current worklog/binding revisions. Include uncategorized minutes in work-type denominators. Preserve old `work.set` parsed input/hash and exact stored outcomes; optional output additions must not inject defaults into old replay JSON.
- Task-table time writes require an explicitly selected period. Server task/package projections include unloaded detail sources; deduplicate packages across pages and never sum loaded projections into an authoritative period total. Active zero, missing and void sources remain distinct.
- Meeting creation proposes personal plans but does not write plans or attendance automatically. Keep the current meeting locator canonical before the first fact. Generic task/manual commands must not bypass meeting roster/schedule/package guards. Meeting occurrence attribution and attendance source identity remain immutable across metadata changes and category recategorization; current attendance reads join the latest worklog head. Old manual commands and cached outcomes stay unchanged when recorded-work output unions expand.
- Recurrence materialization reuses an in-transaction meeting primitive without nesting public write runners. A mandatory same-transaction census protects freezes, including cancelled header-only identities; personal census follows the current materialized roster and falls back to the source-version roster for header-only occurrences. Ordinary writes may complete a bounded prerequisite atomically, but incomplete census must never commit partial baselines or proposed user writes.
- Recurrence worker jobs resolve current stored authorizers server-side before durable receipt replay; never trust a payload actor or impersonate the authorizer. Pending/stale worker continuations commit in the same UOW, while manual chunks use signed cursors. Runtime workers never install or repair queue schemas; explicit local migration owns queue/DLQ setup. P4b current date commands preserve old task input hashes and optional output additions without defaults; accepted bounded imports retain the same current authorization, cutoff, status and field policy through shared in-scope primitives.
- Dependencies are separate from the parent tree and package lineage. Current blocking uses all active workspace edges, including archived/filter-hidden predecessors; only a predecessor in the done status group resolves it. Cycle checks have no UI graph cap. The graph projection has at most 100 explicit roots, depth 0–2, 500 nodes and 1000 edges; overflow is an error, never silent truncation.
- Every task status writer uses the mandatory shared status policy, including recurrence whole-edit preflight and the internal composer. Enforce controls status changes only; graph positions never become dates or effort. Personal layout writes retain hidden positions on explicit full-set save and bypass every cutoff/materialization loop while retaining current access, revision and idempotency checks.
- Calendar dates are plain YYYY-MM-DD in years 0001–9999, with inclusive due dates and shared final start<=due checks. Generic task dates cannot move meetings. The new atomic schedule command checks current target access before exact replay, validates all rows before writes, uses the same endpoint-project census footprint as preview, and compares relevant semantic sources after cutoff prerequisites before any proposed dates. Missing historical startDate is not_captured, never silently null/current-backfilled.
- Import raw UTF-8 without repairing invalid bytes or stripping the accepted BOM from its digest. CSV is bounded to 1 MiB, 50 data rows, 100 columns and five existing scalar field types; every duplicate source ID is blocking. Preserve external IDs as strings, independent task/participant/package/field revision guards and all normalized mapping decisions/units. Preflight every row, then create tasks/values/references/reconciliation atomically through shared in-scope primitives, never nested public runners. Known private source rows stay blocked even if preserved; imported current hours never become original package estimates, plans or worklogs.
- Local MCP credentials must be current inside the authorized read snapshot or after the workspace barrier before any write receipt. Discovery reauthorizes every tools/list; stable pagination never grants lasting access. Keep bearer secrets out of command variables, caches, audit, outbox, URLs and logs; credential attribution is separate from unchanged task payload hashes. Credential lifecycle is inert with respect to cutoffs/materialization, while task tools use the existing mandatory rules.
- Do not deploy, publish, provision paid services, send invitations or external messages, change secrets, or perform destructive data operations without the user's authorization.
- Before reading or editing a sibling product, announce the target, inspect its Git state and read local instructions. Do not import sibling product source at runtime.
- Verify only the affected scope. Documentation changes require link and consistency checks; implementation requires the milestone's meaningful tests. No website build is needed for documentation-only changes.
- If Claude CLI is used, pass `--model opus` unless Pavel requests a different model; preserve actual review provenance.
