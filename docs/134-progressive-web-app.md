# 134 · Workloom как PWA

## Установка

Открыть Workloom в поддерживаемом браузере, войти и выбрать **меню профиля → Install Workloom → Install app**. Приложение открывается с домашнего экрана/дока в отдельном окне. Если браузер не предоставляет установочный диалог, Workloom показывает инструкции для меню браузера и Safari на iPhone/iPad. Системный запрос вызывается только кнопкой пользователя; отмена не считается установкой. После подтвержденной установки или запуска standalone пункт установки скрывается.

В установленном мобильном приложении есть нижняя навигация Overview / My tasks / Inbox / Projects. Остальные разделы доступны через верхнее меню. Ссылки используют те же канонические адреса компаний и защиту черновиков, что и обычный интерфейс. Панели учитывают safe-area; мобильный профиль показывает компактный аватар. Все панели используют текущую тему аккаунта.

## Файлы и обновления

- `apps/web/public/manifest.webmanifest`: постоянный `id: /app`, старт `/app/`, scope `/app/`, `display: standalone`. Манифест подключен только к приложению, не к публичному лендингу.
- `public/icons/workloom.svg`: векторный вариант существующего знака переплетения, градиентная индиго-подложка, светлые нити. PNG 192/512, отдельная непрозрачная maskable-иконка 512 и Apple Touch 180. В диалоге используется SVG, в системных оболочках - PNG.
- `features/pwa/install.ts`: отложенный `beforeinstallprompt`, `appinstalled`, определение standalone и iOS standalone. Состояние установки живет в памяти, не в настройках аккаунта. Worker регистрируется только в production-сборке и secure context; Auth callback его не регистрирует.
- `public/app/sw.js`: scope `/app/`, сетевые навигации с публичным reconnect-экраном при потере сети. В Cache Storage записывается только `/app/offline.html`, без cookies при его загрузке. API, write-запросы, Auth callback, ассеты и чужие origins не перехватываются. HTML приложения, ответы API и данные аккаунта не кэшируются. Это не офлайн-редактор и не очередь синхронизации.
- У worker нет `skipWaiting`, `clients.claim` и принудительного reload. Новая версия worker вступает в силу после закрытия прежних окон; при обычном открытии приложение получает актуальный HTML и сборку с сервера. Если меняется протокол offline-кэша, увеличить его версию в worker.
- Статические файлы манифеста и worker отдаются с `no-cache`, а хешированные JS/CSS - с прежним immutable-кэшированием. Явные GET/HEAD `/app` и `/app/` сохраняют вход в SPA: физический каталог `public/app` иначе приводил к 403 от static handler.

Push-уведомления, фоновая синхронизация, локальные копии задач и работа с задачами без сети не добавлены.

## Проверки 13 ноября 2026

- Web: 48 тестов в 10 файлах - установка и отмена/ошибка запроса, манифест и размеры PNG, политика worker, меню профиля, аватар, Projects, Sidebar, What's new и защита черновиков/навигации.
- API: 20 тестов в двух файлах - canonical SPA, манифест/worker/offline MIME и cache headers, security headers. Базы данных не открывались.
- Полный `npm run predeploy` PASS: TypeScript, ESLint, границы, локализация, API build и 14 проверок deploy-скриптов.
- Изолированный Vite production build в `/tmp/workloom-pwa-build` прошел. Активные веб-артефакты не заменялись.
- Реальная production-сборка через изолированный API static server и отдельный временный профиль Chrome: `Page.getAppManifest` без ошибок, `Page.getInstallabilityErrors` пуст, реальный `beforeinstallprompt` дал кнопку Install app. Worker активировался и контролировал страницу; Cache Storage содержал только публичный offline-документ. Сеть отключена -> reconnect-экран; включена -> приложение открылось снова. JS-ошибок нет.
- Нижнее меню и его переходы проверены в эмуляции standalone, светлый и Graphite скриншоты просмотрены. На ширине 390 px страница не скроллится горизонтально, широкая таблица скроллится внутри своего контейнера. Для этого контейнер Projects получил `position: relative`: абсолютный скрытый caption больше не растягивает корневую область прокрутки. Заметка What's new теперь ниже модальных окон и выше нижнего меню.
- Установка в настоящую ОС, физические iOS/Android, их системные панели/клавиатура, реальный Auth в установленном окне и прод для этой версии отдельно не проверены. Данных реального аккаунта не меняли; миграций нет.
