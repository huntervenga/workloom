## Footer in the visible table area — `ef5f5b0`, accepted on `35ec787`

**Defect.** When the table overflows horizontally, the footer text belongs to the full table width, so the loaded budget could fall outside the visible area of the table. The enhanced spec below observed this natively.

**Fix.** Source `ef5f5b0` makes the table scroller (`data-task-table-scroll`) a CSS size container (`@container`). The footer keeps the same semantic `tfoot` row and single full-width `colSpan` cell. Inside that cell, a sticky `left-0` block sized `100cqw` keeps the budget, **Loaded team budget** and the counts inside the scroller's visible width. Package deduplication and the unknown, zero and partial-scope rules are unchanged. It adds no strings, state, observers or APIs. The author could not run tests in their session. Root ran the focused summary/layout tests: 13 passed in 2.99s.

**Enhanced spec `35ec787`.** This spec keeps the original 1440/390 flow unchanged and adds a horizontal stage. On desktop it resizes to 1200 so the table overflows; mobile stays at 390. A real mouse wheel over a visible non-sticky body cell pans until the scroller reaches its end. Read-only checks then cover every footer fragment's bounds and top-most hit, plus zero global overflow, with no writes and unchanged DTOs, draft and context. On old compiled `5267fbd`, both widths failed natively: 4h was not visible after the real pan. Earlier harness attempts are recorded in [25](25-ux-verification.md).
