# 133 · Тема Omnissiah и как добавлять темы

**Что это.** Четвертая тема в настройках профиля (аватар → Settings → Theme): **Omnissiah**, теплая темная палитра Adeptus Mechanicus - сажа, кость, латунь, кармин и медь; сталь, патина и олива для холодных ролей. Источник цветов - палитра владельца `themes/omnissiah/colors.toml` в `personal_config_agent` (терминал, nvim, VS Code).

## Как устроено и как добавить еще одну тему

- **CSS** (`packages/ui/src/styles.css`): тема входит в общий темный блок `:root:is([data-theme="dark"], [data-theme="default-dark"], [data-theme="omnissiah"])` и переопределяет свои роли в `:root[data-theme="omnissiah"]`.
- **Темные исключения в разметке** - вариант `dark-theme:` (`apps/web/src/styles.css`, `@custom-variant`), а не `[[data-theme=dark]_&]`: он действует для любой темной темы. Выходные в календаре отпусков - токен `calendar-weekend` вместо жестких цветов.
- **Список тем** - только в контракте `userThemeSchema` (`packages/contracts/src/user-settings.ts`). Миграция **0040** заменила проверку в базе: вместо списка `('default','dark','light')` - формат имени `^[a-z][a-z0-9-]{0,39}$`. Новая тема больше не требует миграции.
- **Новая тема:** имя в `userThemeSchema` и `parseTheme`/`Theme` (`apps/web/src/features/theme/ThemeManager.ts`, цвет панели браузера в `CHROME`), селектор в темных списках (`packages/ui/src/styles.css`, React Flow в `apps/web/src/styles.css`, `dark-theme`), свой блок токенов, пункт и подпись в `ProfileSettingsDialog` и `profile.json`, палитра в циклах `themeTokens.test.ts`.
- Публичная главная (лендинг) и экран до входа по-прежнему светлая/темная по системе: выбранная тема приходит из настроек пользователя после входа.

## Все темы рабочего стола и Appearance (13 ноября 2026)

В Settings появились отдельные разделы **Profile** и **Appearance**. Appearance содержит системный Default, затем группы **DARK** и **LIGHT** с небольшими карточками-превью интерфейса. Сетка: три колонки на широком экране, две на телефоне. Выбранная карточка выделяется рамкой и радиокнопкой; сохранение по-прежнему автоматическое через аккаунт, с прежними проверками пользователя, ревизии и ошибок.

Перенесены все 29 палитр из `personal_config_agent/themes/*/colors.toml`, включая уже существующую Omnissiah. Исходные фоны сохранены; роли текста, акцентных кнопок и диаграмм адаптированы под контраст Workloom. В каталоге `apps/web/src/features/theme/palettes.ts` находятся имена, режимы и цвета миниатюр; в `packages/ui/src/styles.css` - полные семантические роли. Стандартные Dark/Light и системный Default сохранены. Новых миграций нет.

Для следующей темы добавлять имя в `userThemeSchema`, запись в `desktopPalettes`, CSS-роли и, если тема темная, ее селектор в общие темные списки CSS. ThemeManager берет режим и цвет панели браузера из каталога. ProfileSettingsDialog строит карточки по каталогу. Собственные имена палитр сохраняются без перевода, точные исключения перечислены в аудите локализации.

Проверки: 55 тестов в четырех файлах (ThemeManager, настройки профиля, аватар, токены/контраст); все палитры проверены на контраст текста и кнопок, серии диаграмм и соответствие контракту. Браузерная проверка с подставным API: Graphite -> Kanagawa Lotus, 32 радиокнопки, отсутствие ошибок JavaScript и горизонтального переполнения на ширине 390 px. Скриншоты темной/светлой и мобильной сетки проверены локально. Реальный аккаунт и прод не изменялись.

Финальные проверки: `npm run predeploy` PASS (общий TypeScript, ESLint, границы, локализация, API build и 14 проверок deploy-скриптов); Vite production build PASS с выводом в `/tmp/workloom-theme-build`, без замены активных веб-артефактов.
