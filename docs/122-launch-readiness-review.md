# Проверка готовности к запуску (22–23 октября 2026)

Статус: ночной обзор «глазами будущего пользователя» плюс ревью нового кода. Всё ниже получено чтением кода и автоматическими тестами; главный авторизованный UI, реальный вход и production **не проверялись** (расширение Chrome не открывает `127.0.0.1`).

## Исправлено в этом проходе

| Область | Проблема | Исправление |
| --- | --- | --- |
| Public API | Токен только с `tasks:write` записывал задачу, затем получал 403 при чтении ответа; повтор без `Idempotency-Key` создавал дубль. | `tasks:write` подразумевает `read` (в принципале токена). Тест в `public-api.test.ts`. |
| Public API | Подделанный курсор пагинации давал 500. | Курсор принимается только в виде, который пишет сам сервер (дата или ISO-момент с миллисекундами), иначе 400. |
| Public API | 50-токенный лимит можно было обойти параллельными запросами. | Консультативная блокировка `pg_advisory_xact_lock` на пользователя при выпуске. |
| Продолжение задачи | Если выбранный проект отклонял новую задачу (архив, нет прав, правило), старая оставалась закрытой без продолжения. | Закрытие откатывается к прежнему статусу; ключи шагов учитывают ревизию, поэтому повтор закрывает заново. Тест «leaves the old task open…». |
| Копия проекта / продолжение | Ключи идемпотентности шагов зависели от порядкового номера секции/поля/отчёта. | Ключи строятся по id сущности. |
| Импорт отсутствий | «Skip rows» помечал строку готовой с пустым сотрудником; ключ строки переиспользовался после смены файла/причины; отрицательные балансы одобрялись молча. | Пустой выбор не считается сопоставлением; ключ привязан к точному запросу и сбрасывается при новом файле; отрицательный баланс импортируется только по явной галочке. |
| Суммы подзадач | При фильтре у родителя показывалась сумма только видимых подзадач. | Суммы отключены, пока действует фильтр. |
| Список задач | Задачи после первых 100 (включая «No section» и новые) прятались за кнопкой. | Страницы догружаются сами (до 1000 задач). |
| Тесты | 5 тестов таблицы устарели после решения «деревья свёрнуты по умолчанию». | Тесты раскрывают родителя. |
| Интерфейс | Нет быстрого перехода; пустой «My tasks» у нового человека говорил «No tasks match these filters»; список первых шагов начинался с команды. | **Ctrl/Cmd+K** — переход к странице, проекту или своей задаче (кнопка поиска в верхней панели); отдельный пустой экран «You have no open tasks»; первый шаг теперь «Add a project». |

## Ещё исправлено после второго круга ревью

- Public API и `/mcp`: встроенный ограничитель частоты (300 запросов в минуту на токен, 600 в минуту на адрес без токена; ответ 429 с `Retry-After`) и потолок пакета JSON-RPC в 20 сообщений.
- «Continue» (одиночное и по выделению) инвалидировало несуществующий префикс кэша, поэтому списки задач, My tasks и отчёты оставались старыми; теперь обновляются.
- Диалоги копирования проекта, продолжения и «New task defaults» не закрываются, пока исход записи неизвестен (иначе повторная отправка создавала дубль); «New task defaults» закрывается после сохранения даже при смене ревизии формы.
- Просроченные записи попыток входа удаляются при создании новой (неаутентифицированный `GET /api/v1/auth/login` раньше мог копить строки).

## Добавлено в ходе обзора

- **Delete task** теперь каскадно убирает активные подзадачи родителя (в той же транзакции, с общей меткой времени); Undo/Restore родителя возвращает ровно их, подзадача, удалённая раньше отдельно, остаётся удалённой; подзадачу нельзя восстановить, пока удалён её родитель (раньше дети оставались «живыми» с архивным родителем). Тест `task-archive-cascade.test.ts`.
- **Перенос недели одной кнопкой:** после «Create next copy» в диалоге появляется «Carry over N unfinished tasks…» (открытые задачи верхнего уровня без подзадач-вложений, только если загружен весь проект без фильтров) — массовое «Complete and continue» с уже выбранным новым проектом. Подзадачи не переносятся отдельно.
- **Continue in another project…** в панели выделенных задач (массовое продолжение).
- **Inbox** и **Ctrl/Cmd+K** (см. выше).

## Замечено ревью задач, но не изменено

- `updateTask` (PATCH) позволяет подзадаче сменить раздел и родителя без проверок, которые есть у bulk и move; снятие родителя оставляет «корню» общий пакет работ.
- Ручной порядок: создание/перемещение читает и перенумеровывает весь проект (O(N) записей под барьером workspace) — медленно на проектах в тысячи задач.
- `updateTask`/`archiveTask` не проверяют, что проект открыт (архивный проект можно править через PATCH).
- Отменённый (cancelled) предшественник блокирует зависимые задачи навсегда, пока ребро не удалено.
- Продолжение: если шаг зависимости (после создания задачи) не удался, старая остаётся закрытой, а новая без связи — повторный запрос с тем же ключом доводит дело до конца.

## Замечено ревью Time off, не изменено (решения владельца)

- Администратор может утвердить заявку и создать запись без проверки баланса (`leave.manage` делает ограничения советом), это согласуется с docs/119, но расходится с формулировкой docs/91 «отрицательный баланс только по явному согласию».
- Утверждение ожидающей заявки не проверяет пересечения с уже утверждённой записью, созданной администратором; расчёт списывает день один раз, а в журнале `leave_charge_ledger` будет два списания (читателя у журнала пока нет).
- Типовые флаги (расходует баланс, пауза накопления, недоступность) берутся из снимка на момент создания заявки, а не на момент утверждения.
- Сотрудник не может отозвать ожидающую заявку, у которой дата начала уже наступила.
- Сотрудники видят «локальную дату» коллег (часовой пояс с точностью до часа).
- Строгая проверка трудоустройства для не-менеджера смотрит на все календарные дни, а не на списываемые (пятница–воскресенье при окончании в пятницу отклоняется).
- Бюджет расчёта: профили с очень старой датой учёта (например 1900 год) могут дать `LEAVE_CALCULATION_LIMIT` для всего обзора.

## Второй заход (по решению владельца)

- **@упоминания в комментариях** (миграция 0032 `task_comment_mentions`, применена локально; дамп до миграции вне репозитория): в поле комментария после `@` появляется список участников; выбранные имена превращаются в упоминания, человек видит их в Inbox («mentioned you»), даже если не участвует в задаче; свои и чужие workspace игнорируются; комментарий, упоминающий ответственного, показывается один раз.
- **Inbox** показывает также решения по вашему отпуску и очередь заявок на утверждение (для тех, у кого есть право `leave.approve`).
- **Заголовки безопасности:** `Content-Security-Policy` для страниц (скрипты только свои + хеши встроенных скриптов сборки, без `unsafe-eval`, без фреймов, соединения только на свой origin), `default-src 'none'` для ответов API, `Permissions-Policy`, `Strict-Transport-Security` в hosted-режиме. Проверено в настоящем Chrome на лендинге, `/docs` и `/app`: ошибок CSP нет (вход через настоящий провайдер не проверялся).
- **Маршруты на cookie-сессии** (`/api/v1/auth/*`, приём приглашений, создание workspace) ограничены по адресу (120 запросов в минуту); для работы за reverse proxy добавлена `TRUST_PROXY_HOPS` (0–5, по умолчанию 0). Лимит: не более 25 собственных workspace на пользователя.
- **Time off:** сотрудник может отозвать ожидающую заявку, даже если дата начала уже наступила; коллеги больше не видят «локальную дату» друг друга. Пересечение при утверждении **не** блокируется (владелец принимал такие случаи, docs/112), флаги типа берутся из снимка заявки, проверка занятости по календарным дням и бюджет расчёта не менялись.
- **Лендинг** (`/`): «Try for free» → страница `/start` (создать аккаунт или войти, обе кнопки ведут в общий вход Google `/api/v1/auth/login`), настоящие скриншоты на синтетических данных (`apps/web/public/shots`), преимущества и честные ограничения, FAQ, JSON-LD (SoftwareApplication + FAQPage), Open Graph/Twitter, sitemap с `/start`. Скриншоты сняты на одноразовой базе с выдуманной командой, не на рабочих данных.

## Третий заход: перенос из Asana и удобство

- **Импорт из Asana** теперь доступен и на хостинге (владелец workspace, общий вход): диалог начинается с инструкции, как получить два файла (стрелка у названия проекта → Export/Print → CSV, затем JSON) и напоминает добавить людей на страницу Members с теми же e-mail. Журналы импорта лежат в `ASANA_IMPORT_DIR` (по умолчанию временный каталог ОС). Ваш план «импорт и проверка локально, потом перенос базы на прод» от этого не меняется.
- **Состояние интерфейса запоминается в браузере** (по пользователю, workspace и проекту): вид (таблица/доска/граф/таймлайн), сортировка, фильтры и группировка; возвращаясь в проект из сайдбара, вы видите его таким, каким оставили. Ссылка с явными параметрами всегда главнее. Уже запоминались: раскрытые задачи/секции, тема, закладка Inbox, колонки таблицы (на сервере).
- **Меньше шума:** нет пустых строк «Group total» и подвала итогов, пока итоги не выбраны; «Column totals» без рамки в свёрнутом виде и скрыт у тех, кто не может его настроить; счётчики «loaded tasks» убраны с доски; подсказка про автосохранение убрана из панели задачи (подсказка теперь в поле описания); кнопка Refresh — только значок; Local MCP спрятан в раскрывающийся блок; плитки «Time zone / Your role / Team» с Overview убраны.
- **Overview:** сверху «Your next tasks» (до пяти ближайших по сроку), адрес компании и «API & integrations» убраны в раскрывающийся «Workspace settings».
- **My tasks** сгруппирован по срокам: Overdue / Today / This week / Later / No due date.
- **Copy link** в панели задачи (ссылка вида `/app/w/…/projects/…?task=…`).

## Что не хватает для запуска (по важности)

1. **Уведомления.** Сделан **Inbox v1** (страница Inbox в сайдбаре, `GET /api/v1/workspaces/:ws/inbox`, без миграции): за 30 дней показывает, что кто-то другой назначил вас на задачу или написал комментарий к задаче, где вы ответственный или участник; «непрочитанное» — закладка в браузере (localStorage), бейдж в сайдбаре. Ещё нет: @упоминания, решения по отпускам, e-mail и push, общее «прочитано» между устройствами (нужна таблица).
2. **Приглашения письмом.** Ссылку приходится передавать вручную (`team.json`: «No email is sent»), а приглашённый обязан войти с точно этим подтверждённым e-mail.
3. **@упоминания в комментариях** (строка подсказки говорит только про Cmd/Ctrl+Enter).
4. **Сохранённые представления** (фильтры только в URL).
5. **Горячие клавиши** помимо Ctrl/Cmd+K: `n` — новая задача, `/` — поиск, `?` — шпаргалка.
6. **Шаблоны** задач/проектов с задачами (копия проекта без задач уже есть).
7. **Rate limit на токен** публичного API и потолок размера JSON-RPC-пакета в `/mcp`.
8. **Мобильная вёрстка** таблицы, Timeline и Graph не проверена (нужен прогон на 390 px).
9. **Тексты**: сленг («Baseline deadline», «Requested cutoff», «unconfirmed … retry its original submission»), смесь регистров, «Assign & approve» рядом с двумя формулировками про отрицательный баланс; нужен проход редактора.
10. **Причина отклонения отпуска** и уведомление заявителя не найдены в строках.

## Что проверено и найдено корректным

Хеш токенов и сравнение, отзыв/срок действия, ограничения по workspace, IDOR между workspace, MCP не шире REST, исключения Origin-защиты только для bearer-маршрутов, отсутствие секретов в логах, лимиты размеров запросов, отсутствие исходящих запросов. Значения по умолчанию: явное значение вызывающего всегда главнее. Точность оценок: деление на ноль защищено, тренд только от 4 периодов. Автоподгрузка ограничена 1000 задач и не зацикливается.
