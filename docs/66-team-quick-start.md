# Workloom: быстрый старт для команды

Практическая памятка для 5–7 человек, которые пробуют текущий локальный Workloom. Элементы интерфейса названы точно так, как они написаны в английском UI. Чтобы попробовать сценарии ниже, контракты читать не нужно; ссылки ведут к подробностям.

## Что это сейчас

- **Локальная версия на синтетических данных.** Входа в систему нет. В верхней панели стоит значок **Local demo** (на узком экране — **Test**) с подсказкой «Local mode with synthetic data». В боковой панели карточка показывает текущего тестового пользователя и его роль; **Switch user** выбирает другого участника (Synthetic Owner, Admin, Member A/B/C, Viewer), а раскрывающийся **Local demo** поясняет «Synthetic data. No sign-in required.». Так проверяются роли, но это не настоящий Auth. Нет входа, приглашений и приватных ACL: задачи, встречи и отчёты видны всему workspace. Реальные личные данные, часы и клиентскую информацию не вносить.
- **Язык интерфейса.** Сейчас UI на английском; новый язык добавляется JSON-каталогами без правки кода ([23](23-localization-and-ux.md#add-a-language)). Названия задач, проектов, статусов и полей отображаются так, как их ввели.
- **Чего нет.** Production deployment, подключения внешних календарей, перетаскивания дат в Timeline и полного переноса из Asana нет. Подключение календарей — будущий дизайн из [10](10-calendar-integration.md). Импорт сейчас ограничен небольшим CSV ([19](19-p5-import-contract.md)).

## Подготовка локальной демонстрации (делает ведущий)

1. Приложение слушает только `127.0.0.1`, поэтому команда работает за компьютером ведущего или смотрит демонстрацию его экрана. Постоянная демо-база уже есть; её запускает managed helper из [26](26-local-runtime.md). На Node.js 24 из корня репозитория:

   ```sh
   node scripts/local-runtime.mjs doctor   # состояние PostgreSQL, API и web
   node scripts/local-runtime.mjs start    # существующий кластер, собранный API и web
   ```

   `start` переиспользует уже запущенные проверенные процессы, поэтому второй API (в том числе `npm run dev` поверх) не запускать. Собранное приложение — http://127.0.0.1:4310, интерфейс разработки — http://127.0.0.1:4311. Helper ничего не собирает, не мигрирует и не сбрасывает; worker остаётся выключенным. Не заменять `.env`, не пересоздавать и не очищать базу. Установка новой копии — отдельный путь в [README](../README.md#локальный-запуск).
2. Workspace **Workloom Studio** с проектами **Product launch** и **Team operations** ([27](27-synthetic-demo.md)) — эталонный пример, его только смотрим. Для собственных проб создать отдельный проект через **New project**.
3. Заранее раздать роли: кто играет Owner/Admin, кто Member, и обязательно одного Viewer, чтобы увидеть режим только для чтения.
4. Worker выключен, и без координации его не включать. Серии встреч и фиксация по дедлайну в фоне не готовятся. После срока baseline фиксируется при следующей защищённой записи ([38](38-cutoff-automation-contract.md), [43](43-managed-local-worker.md)).

## Реальная команда — отдельный этап

Переносить реальную работу можно только после этих шагов: Shared Auth, настоящее участие и приглашения, приватные права во всех представлениях; разрешённый выпуск на площадку ([08](08-railway-and-operations.md), ресурсы пока не созданы) с резервным копированием; согласованный пробный импорт из Asana со сверкой. Порядок — в [21](21-local-pilot-handoff.md#что-готово-и-где-граница) и [07](07-verification-and-pilot.md#перенос-команды).

## Сценарии

**1. Workspace и проект.** В боковой панели выбрать пространство (**Choose a workspace**), затем **Projects** → проект. **My tasks** показывает ваши задачи из всех проектов по сроку; список только для чтения, строка открывает задачу в её проекте. Представления проекта: **Tasks**, **Board**, **Graph**, **Timeline**, **CSV import** (только owner/admin), а также ссылка **Week**.

**2. Задача и подзадача.** **Add task** открывает полную форму (**Create task**). В секции работает быстрое добавление: Enter добавляет задачу, Escape оставляет черновик, **More details** открывает все поля. Чтобы создать подзадачу, откройте задачу и выберите **Add subtask**. В **Subtask scope** есть два варианта:

- **Detail — included in the parent estimate** — подзадача делит пакет работы родителя;
- **Additional work — separate estimate** — подзадача получает отдельный пакет.

Строка появляется только после подтверждения сервера.

**3. Редактирование в строке.** Клик по названию открывает карточку задачи; переименовать в строке можно карандашом рядом с названием (подсказка «Rename …»). Клик по ячейке Status, Assignee, Priority, Due date или **Team estimate** открывает редактор этой ячейки. Выбор значения и уход из поля ничего не сохраняют. Сохраняет кнопка **Save** в любом редакторе или ⌘/Ctrl+Enter. Простой Enter сохраняет только в текстовых полях названия и **Team estimate**; в списках Status, Assignee и Priority он не сохраняет. **Collapse editor** или Escape сохраняет черновик в памяти, а строка показывает **Draft**. Сложный черновик продолжается через **Resume draft** или **More details**. У встреч, архивных задач и у Viewer редактирования в строке нет. В новых проектах колонка Priority по умолчанию скрыта — включить её можно через **Columns** ([62](62-inline-task-priority.md)). Если ячейка у края широкой таблицы, при открытии редактора таблица сама сдвигается по горизонтали, чтобы поле и кнопки были видны; страница не прокручивается, фокус не перескакивает ([65](65-inline-editor-layout.md)).

**4. Личные колонки.** На **Tasks** кнопка **Columns** открывает **My task columns**: видимость, порядок (стрелки вверх/вниз), **Save columns**, **Use project defaults**, **Discard changes**. Выбор относится только к вашему виду этого проекта. Общие колонки проекта (**Team columns**) настраивает owner/admin, и личный выбор их не меняет. Фильтры, сортировка, группировка и ширины не сохраняются; именованных видов нет. Колонки **Personal weekly plan** и **Personal actual hours** доступны после выбора недели и человека ([32](32-personal-table-columns.md)).

**5. Фильтры, группировка, сортировка.**

- **Поиск и фильтры.** Есть **Search tasks** и **Filters**: **Task status**, **Task participant**, **Task tag**, **Show archived tasks**, **Clear filters**. Активные условия видны отдельными кнопками, например **Clear status filter: In progress**; такая кнопка снимает только своё условие.
- **Group by.** **Section** или **Assignee**. Каждая задача показывается один раз; встреча попадает к организатору. Фильтр Participant и группировка Assignee — разные вещи.
- **Sort.** **Manual** или **Due date**. Сервер упорядочивает весь проект; подзадачи остаются под родителем, задачи без срока идут последними. Пояснение — в **About this table**.
- **Итог внизу.** **Loaded team budget** считает только загруженные задачи, общий пакет учитывается один раз (**Shared estimates counted once.**). Это не итог проекта или недели; следующую страницу загружает **Load more tasks**. Строка итога остаётся в видимой части таблицы и при горизонтальной прокрутке ([63](63-table-guidance.md)).

На **Board** доступны фильтры и сортировка, на **Timeline** — только поиск и фильтры, на **Graph** панели нет ([59](59-contextual-project-toolbar.md)).

**6. Сначала неделя и человек, потом часы.** В панели таблицы выбрать **Week** (по умолчанию **Choose a week explicitly**) и **Person**. Без недели часы не вводятся. **Person** меняет показанные часы, но не список задач и не того, кто действует (**About hours**). Свои план и факт вводит участник, чужие — owner/admin.

Ссылка **Week** переносит выбранные неделю и человека на недельную страницу, **Back to task table** возвращает обратно. Там **Time entry for** задаёт, для кого вводятся новые записи, а вкладки — **Plan and hours**, **Report**, **Work types**. Факт вводится на всю неделю, без разбивки по дням: **Record actual hours** → **Save actual hours**. Пусто — неизвестно, 0 — подтверждённый ноль. Исправление или **Void this entry** требует **Reason for correction**.

**7. Общая оценка и личные часы.** **Team estimate** — общий бюджет всего пакета работы на всю команду: пусто — **Not estimated**, 0 — оценка ноль. Личный недельный план и факт задаются отдельно по каждому человеку и из оценки не выводятся. У встречи **New meeting** общий бюджет равен длительности, умноженной на число участников. Создание встречи не пишет ни план, ни часы. План применяется явно: **Preview personal plans** → **Apply personal plans**. После встречи:

1. **Save actual details** — фактические начало и длительность;
2. присутствие — **Confirm selected person's attendance** или **Confirm team attendance**;
3. варианты: **Attended entire meeting**, **Attended part of meeting**, **Absent · 0 minutes**. Неизвестное присутствие не создаёт факт.

Часы встречи не вводятся как обычный недельный факт ([15](15-p3a-contract.md), [30](30-time-context-ux.md)).

**8. Зависимости — Graph, даты — Timeline.**

- **Выбор задач.** Отметить задачи в таблице (**Select for graph: …**) и открыть **Selected graph (N)**. Дальше настраивается **Neighbor depth** и вид: **Dependency list** или **Diagram**.
- **Связи.** **Add dependency** создаёт связь finish-to-start, в том числе между проектами одного workspace; циклы отклоняются.
- **Правило блокировки.** В **Project blocking rule** выбрать **Warn and allow status changes** или **Block start and completion until predecessors finish**, затем **Save blocking rule**. Предшественник считается завершённым только в группе статусов done; список даёт **View blockers (N)**.
- **Раскладка.** Карточки в **Diagram** перетаскиваются мышью; **Save my layout**, **Discard moves** и **Apply automatic layout** меняют только ваши личные позиции, не даты и не трудозатраты. Физический touch не проверен ([60](60-graph-dragging.md)).
- **Даты.** **Timeline** показывает загруженные задачи в окне 28/84/366 дней (**Days in window**). Отметить задачи → **Edit selected dates (N tasks)** → ввести даты или **Move one day earlier**/**Move one day later** → **Preview changes** → **Apply dates**. Перетаскивания и каскадного сдвига нет, часы в длительность не превращаются. Даты встреч меняются в их календаре. **Compare with a frozen plan** накладывает исходный план: если старая дата не сохранялась, видно «…was not captured in this plan», а не текущая дата ([18](18-p4b-contract.md)).

**9. Отчёты: baseline, «неизвестно» и 0.**

- **Baseline.** **Save my baseline** или **Save project baseline** сохраняет неизменяемый снимок после серверного предпросмотра.
- **Отчёт.** **Set up new report** → **Calculate new report** создаёт закреплённый отчёт. Поздние исправления попадают только в новый отчёт.
- **Пустые значения.** **Not set** — план неизвестен. **Not recorded** или пунктир — записи нет, это не ноль. Подтверждённый 0 — отдельная запись. При неполных данных общее отклонение не показывается.
- **Типы работы.** В **Work types** часы без категории входят в знаменатель долей.
- **Итоги.** Суммы берутся из отчёта сервера, а не из видимых строк ([13](13-p2a-contract.md), [14](14-p2b-contract.md)).

## Если запись зависла или не прошла

- **Повтор только явный.** Автоповтора и офлайн-очереди нет. Пока запрос в пути (waiting for server response) или его результат неизвестен (save result unknown), форма держит отправленные значения закрытыми. Повторять нужно предложенной кнопкой: **Retry**, **Retry original**, **Retry original save**, **Retry original dates**, **Retry original columns**. Найти исходную форму помогают **Resume original editor**, **Open original hours save** и **Resume column save**. Повтор отправляет то же содержимое с тем же ключом и дубля не создаёт. Не создавайте запись заново, пока не проверили, что уже сохранено на сервере.
- **Конфликт.** Если кто-то изменил данные раньше вас, черновик не перезаписывается: **Load latest version**, **Review changes** или **Reload and review**. Для личных колонок после конфликта **Discard changes** перечитывает текущие настройки, а ошибка закрытого окна показывает **Review columns**. **Reload and review** переносит черновик на новую версию только после подтверждённого конфликта; в остальных случаях он сохраняет исходную версию, а несохранённая или неподтверждённая запись не сбрасывается. Если доступа нет, сообщение нейтрально: оно не утверждает, сохранились ли настройки, — проверьте их после восстановления доступа ([64](64-personal-columns-recovery.md)).
- **Черновики живут только в памяти страницы.** При уходе спрашивается **Leave this page?**: **Stay** или **Leave without saving**. Перезагрузка, закрытие вкладки, смена пользователя и осознанный уход теряют черновик и ключ повтора.
- **После перезапуска API или обновления.** Если после перезапуска API список выдаёт ошибку, перезагрузите его. Старая вкладка после обновления показывает **Workloom has been updated** → **Refresh tab**, адрес сохраняется.
- **Если пишете о проблеме.** Укажите пользователя, представление, шаги, точные надписи и **Request ID:**, если он показан. Секреты и содержимое `.env` не прикладывать.
