# Workloom: быстрый старт для команды

Практическая памятка для 5–7 человек, которые пробуют текущий локальный Workloom. Элементы интерфейса названы точно так, как они написаны в английском UI. Чтобы попробовать сценарии ниже, контракты читать не нужно; ссылки ведут к подробностям.

Текущая локальная версия — **`bd8ce21`**: baseline `7b9a712`, исправленный Graph wrap `2f71ad8` и обновляемые locale/accessibility labels Graph. Широкие web **1367/171** и **101 разный native** относятся к baseline; новые узкие проверки и 30-минутный soak имеют отдельные scopes в [71](71-night-verification.md). Действия и recovery ниже приняты в указанном bounded local scope; интерфейс пока English/LTR.

## Что это сейчас

- **Локальная версия на синтетических данных.** Входа в систему нет. В верхней панели стоит значок **Local demo** (на узком экране — **Test**) с подсказкой «Local mode with synthetic data». В боковой панели карточка показывает текущего тестового пользователя и его роль; **Switch user** выбирает другого участника (Synthetic Owner, Admin, Member A/B/C, Viewer), а раскрывающийся **Local demo** поясняет «Synthetic data. No sign-in required.». Так проверяются роли, но это не настоящий Auth. Нет входа, приглашений и приватных ACL: задачи, встречи и отчёты видны всему workspace. Реальные личные данные, часы и клиентскую информацию не вносить.
- **Язык интерфейса.** Сейчас UI на английском; новый язык добавляется JSON-каталогами без правки кода ([23](23-localization-and-ux.md#add-a-language)). Названия задач, проектов, статусов и полей отображаются так, как их ввели.
- **Чего нет.** Production deployment, подключения внешних календарей, resize дат в Timeline, automatic scheduling и полного переноса из Asana нет. Подключение календарей — будущий дизайн из [10](10-calendar-integration.md). Импорт сейчас ограничен небольшим CSV ([19](19-p5-import-contract.md)).

## Подготовка локальной демонстрации (делает ведущий)

1. Приложение слушает только `127.0.0.1`, поэтому команда работает за компьютером ведущего или смотрит демонстрацию его экрана. Постоянная демо-база уже есть; её запускает managed helper из [26](26-local-runtime.md). На Node.js 24 из корня репозитория:

   ```sh
   node scripts/local-runtime.mjs doctor   # состояние PostgreSQL, API и web
   node scripts/local-runtime.mjs start    # существующий кластер, собранный API и web
   ```

   `start` переиспользует уже запущенные проверенные процессы, поэтому второй API (в том числе `npm run dev` поверх) не запускать. Собранное приложение — http://127.0.0.1:4310, интерфейс разработки — http://127.0.0.1:4311. Helper ничего не собирает, не мигрирует и не сбрасывает; worker остаётся выключенным. Не заменять `.env`, не пересоздавать и не очищать базу. Установка новой копии — отдельный путь в [README](../README.md#локальный-запуск).
2. Workspace **Workloom Studio** с проектами **Product launch** и **Team operations** ([27](27-synthetic-demo.md)) — эталонный пример, его только смотрим. Для собственных проб создать отдельный проект через **New project**.
3. Заранее раздать роли: кто играет Owner/Admin, кто Member, и обязательно одного Viewer, чтобы увидеть режим только для чтения.
4. Worker выключен, и без координации его не включать. Серии встреч и фиксация по дедлайну в фоне не готовятся. После срока baseline фиксируется при следующей защищённой записи ([38](38-cutoff-automation-contract.md), [43](43-managed-local-worker.md)).

## Реальная команда — отдельный этап

Для удалённой реальной работы нужны Shared Auth, настоящее участие/приглашения, изоляция workspace и проверенные текущие роли; разрешённый выпуск на площадку ([08](08-railway-and-operations.md), ресурсы пока не созданы) с резервным копированием; согласованная сверка выбранных рабочих задач при переносе. Первый общий пилот может оставлять все задачи и встречи видимыми всему workspace, если участники явно согласовали такой scope. Private ACL обязательны до использования приватных задач или звонков, но не блокируют общий пилот, в котором приватности нет. Небольшой набор из Asana можно перенести вручную: создать проекты/секции, затем названия задач и проверить ответственных, сроки, статусы и оценки; CSV не является обязательным шагом. Автоматический полный перенос истории, original estimates, личных планов и факта этим не обещается. Порядок — в [21](21-local-pilot-handoff.md#что-готово-и-где-граница) и [07](07-verification-and-pilot.md#перенос-команды).

## Сценарии

**1. Workspace и проект.** В боковой панели выбрать пространство (**Choose a workspace**), затем **Projects** → проект. **My tasks** показывает ваши задачи из всех проектов по сроку; список только для чтения, строка открывает задачу в её проекте. Представления проекта: **Tasks**, **Board**, **Graph**, **Timeline**, **CSV import** (только owner/admin), а также ссылка **Week**.

**2. Задача и подзадача.** В таблице с **Group: Section** кнопка **New task**, строка **Add task…** внизу секции и её **+ Task** открывают быстрое добавление по названию. Enter ставит ровно введённую задачу в последовательную очередь и сразу освобождает поле для следующей. Пустой Enter ничего не создаёт. Подтверждения сервера идут по очереди и не меняют уже набранный следующий текст. При ошибке очередь ждёт: **Retry** повторяет исходную запись, **Discard rejected task** есть только при известном отказе. При неизвестном результате запись не отбрасывается. Escape/**Collapse** сохраняет набранный черновик в памяти; **More details** переносит его в полную форму. В Board/Graph/Timeline/Import и группировке по ответственному **New task** открывает полную форму ([68](68-asana-table-editing.md)).

**Add subtask** создаёт подзадачу:

- **Detail — included in the parent estimate** — делит пакет работы родителя;
- **Additional work — separate estimate** — получает отдельный пакет.

Карточка родителя показывает загруженные прямые подзадачи с полными названиями, статусом и типом scope. При фильтрах или неполной загрузке это явно лишь часть списка; открытие подзадачи сохраняет родительский черновик в памяти.

**3. Редактирование в строке.** У доступной для редактирования обычной задачи клик по названию открывает редактор названия; **Open details** отдельно открывает карточку. У read-only строки название открывает карточку. Enter сохраняет название и для корневой задачи в section grouping сразу открывает следующую строку добавления; ⌘/Ctrl+Enter сохраняет без продолжения. Изменённое текстовое поле также сохраняется при реальном уходе фокуса. В Status/Assignee/Priority собственный список сохраняет только явно выбранное значение; Escape и нажатие снаружи ничего не записывают. Черновики и неизвестные результаты восстанавливаются исходными действиями страницы, не повторным созданием задачи. Табличная сетка остаётся41px и не расширяет колонку при открытии редактора ([68](68-asana-table-editing.md)).

**Move to section** в действиях строки перемещает обычную корневую задачу в активную секцию или **No section**. Оно не меняет проект, parent, статус, участников, пакет или часы. Подзадачи, встречи и архивные/read-only строки этим действием не перемещаются. Нет перетаскивания между секциями.

**4. Личные колонки.** На **Tasks** кнопка **Columns** открывает **My task columns**: видимость, порядок (стрелки вверх/вниз), **Save columns**, **Use project defaults**, **Discard changes**. Выбор относится только к вашему виду этого проекта. Общие колонки проекта (**Team columns**) настраивает owner/admin, и личный выбор их не меняет. Фильтры, сортировка, группировка и ширины не сохраняются; именованных видов нет. Колонки **Personal weekly plan** и **Personal actual hours** доступны после выбора недели и человека ([32](32-personal-table-columns.md)).

**5. Фильтры, группировка, сортировка.**

- **Поиск и фильтры.** **Search tasks** доступен над списком и на узком экране; строка поиска остаётся в памяти. Отдельный **Task completion** предлагает **All tasks** и **Incomplete tasks**: второй вариант показывает серверный список статусов `todo`/`in_progress`, включая собственные статусы. Выбор хранится как `completion=open` в URL и восстанавливается при reload и Back/Forward; **All tasks** удаляет только этот параметр. В **Filters** есть: **Task status**, **Task participant**, **Task tag**, **Show archived tasks**, **Clear filters**. Status/participant/tag/archived также хранятся в URL проекта и восстанавливаются при reload и Back/Forward. Активные условия видны отдельными кнопками, например **Clear status filter: In progress**; такая кнопка снимает только своё условие.
- **Group by.** **Section** или **Assignee**. Каждая задача показывается один раз; встреча попадает к организатору. Фильтр Participant и группировка Assignee — разные вещи.
- **Sort.** **Manual** или **Due date**. Сервер упорядочивает весь проект; подзадачи остаются под родителем, задачи без срока идут последними. Пояснение — в **About this table**.
- **Итог внизу.** **Loaded team budget** считает только загруженные задачи, общий пакет учитывается один раз (**Shared estimates counted once.**). Это не итог проекта или недели; следующую страницу загружает **Load more tasks**. Строка итога остаётся в видимой части таблицы и при горизонтальной прокрутке ([63](63-table-guidance.md)).

На **Board** доступны фильтры и сортировка, на **Timeline** — только поиск и фильтры, на **Graph** панели нет ([59](59-contextual-project-toolbar.md)).

**6. Сначала неделя и человек, потом часы.** В панели таблицы выбрать **Week** (по умолчанию **Choose a week explicitly**) и **Person**. Без недели часы не вводятся. **Person** меняет показанные часы, но не список задач и не того, кто действует (**About hours**). Свои план и факт вводит участник, чужие — owner/admin.

Ссылка **Week** переносит выбранные неделю и человека на недельную страницу, **Back to task table** возвращает обратно. Там **Time entry for** задаёт, для кого вводятся новые записи. **Show → All people** по умолчанию показывает все сохранённые планы и часы; **имя (me)** или другой человек меняет только показанный список. Этот lens не меняет исполнителя новой записи или состав отчёта; скрытые строки с черновиками можно вернуть через **Show all people**. Вкладки — **Plan and hours**, **Report**, **Work types**. Факт вводится на всю неделю, без разбивки по дням: **Record actual hours** → **Save actual hours**. Пусто — неизвестно, 0 — подтверждённый ноль. Исправление или **Void this entry** требует **Reason for correction**.

**7. Общая оценка и личные часы.** **Team estimate** — общий бюджет всего пакета работы на всю команду: пусто — **Not estimated**, 0 — оценка ноль. Личный недельный план и факт задаются отдельно по каждому человеку. В форме плана **Use shared estimate (…h)** лишь заполняет личный черновик; запись требует **Save personal plan**. **Original estimate** рядом с текущим бюджетом — значение первой связанной фиксации, которое поздние правки не заменяют. **Unknown** означает, что тогда оценки не было; **Not captured yet** — что связанного freeze ещё нет. Известный0 отличается от обоих состояний ([13](13-p2a-contract.md)). У встречи **New meeting** общий бюджет равен длительности, умноженной на число участников. Создание встречи не пишет ни план, ни часы. План применяется явно: **Preview personal plans** → **Apply personal plans**. После встречи:

1. **Save actual details** — фактические начало и длительность;
2. присутствие — **Confirm selected person's attendance** или **Confirm team attendance**;
3. варианты: **Attended entire meeting**, **Attended part of meeting**, **Absent · 0 minutes**. Неизвестное присутствие не создаёт факт.

**Meeting followed the plan · fill details** заполняет фактический черновик из плана; сначала сохраните его через **Save actual details**. **Everyone attended · prepare review** затем готовит full attendance только для неподтверждённых людей текущего roster, сохраняя partial/absent/void/saved и собственные несохранённые правки. Это ещё не запись: проверьте выбранные строки и подтвердите team attendance. Отмена встречи не позволяет подготовить всем присутствие.

Часы встречи не вводятся как обычный недельный факт ([15](15-p3a-contract.md), [30](30-time-context-ux.md)).

**8. Зависимости — Graph, даты — Timeline.**

- **Выбор задач.** Отметить задачи в таблице (**Select for graph: …**) и открыть **Selected graph (N)**. Дальше настраивается **Neighbor depth**; **Diagram** показывает направление predecessor → successor, **Dependency list** остаётся отдельным видом. Выбор карточки выделяет её прямых соседей только в этом графе; завершённый predecessor разрешает связь, прочие остаются unresolved. Это не обещание полного списка workspace.
- **Связи.** **Add dependency** создаёт связь finish-to-start, в том числе между проектами одного workspace; циклы отклоняются.
- **Правило блокировки.** В **Project blocking rule** выбрать **Warn and allow status changes** или **Block start and completion until predecessors finish**, затем **Save blocking rule**. Предшественник считается завершённым только в группе статусов done; список даёт **View blockers (N)**.
- **Раскладка.** Карточки в **Diagram** перетаскиваются мышью; **Save my layout**, **Discard moves** и **Apply automatic layout** меняют только ваши личные позиции, не даты и не трудозатраты. Физический touch не проверен ([60](60-graph-dragging.md)).
- **Даты.** **Timeline** один раз подбирает окно28/84/366 дней по текущим датам загруженных обычных задач. После ручного выбора окно не перескакивает при обновлениях; **Fit loaded tasks** подбирает его снова явно. Нет дат — есть отдельная группа и ограниченное окно. Месяцы, дни, выходные и текущий день отмечены на оси; стрелки показывают только доступные current comparisons с обоими endpoint в окне. Пропущенные связи объясняются отдельно. Отметить задачи → **Edit selected dates (N tasks)** → ввести даты или **Move one day earlier**/**Move one day later** → **Preview changes** → **Apply dates**. Либо перетащить текущую сохранённую полосу/точку: отдельный ghost показывает предложение, drop открывает preview, а запись всё равно требует **Apply dates**. На мобильном можно воспользоваться **Edit dates** с клавиатуры. Resize и каскадного сдвига нет, часы в длительность не превращаются ([72](72-gantt-date-move.md)). Даты встреч меняются в их календаре. **Compare with a frozen plan** накладывает исходный план: если старая дата не сохранялась, видно «…was not captured in this plan», а не текущая дата ([18](18-p4b-contract.md)).

**9. Отчёты: baseline, «неизвестно» и 0.**

- **Baseline.** **Save my baseline** или **Save project baseline** сохраняет неизменяемый снимок после серверного предпросмотра.
- **Отчёт.** Открытие вкладки ничего не вычисляет и не записывает. Без явного выбора показывается newest saved report проектного baseline; **Saved report** закрепляет другой сохранённый run. **Calculate current report** явно создаёт новый отчёт по проектному baseline для всех доступных людей. **Set up new report** раскрывает baseline, known-only и состав людей для **Calculate new report**. Scope, as-of и known-only пометка остаются видимы; поздние исправления попадают в новый run. Во **Work types** аналогично работают **Saved breakdown** и **Calculate current breakdown**.
- **Пустые значения.** **Not set** — план неизвестен. **Not recorded** или пунктир — записи нет, это не ноль. Подтверждённый 0 — отдельная запись. При неполных данных общее отклонение не показывается.
- **Типы работы.** В **Work types** часы без категории входят в знаменатель долей.
- **Итоги.** Суммы берутся из отчёта сервера, а не из видимых строк ([13](13-p2a-contract.md), [14](14-p2b-contract.md)).

## Если запись зависла или не прошла

- **В Week не загрузился список задач.** При **Could not load tasks. Your entry is kept.** нажмите **Retry loading tasks**; при ошибке следующей страницы — **Retry loading more tasks**. Уже доступные задачи, выбранные неделя/человек, введённые часы и комментарий сохраняются. Повтор загружает список; запись часов по-прежнему требует явного **Save**.
- **Созданная задача скрыта фильтрами.** Подтверждение **Task “…” created. Your filters are still applied.** означает, что сервер подтвердил создание; **Open details** открывает сохранённую задачу без снятия фильтров. Закройте карточку и снова откройте **Add task…** в исходной секции, чтобы продолжить следующий ещё не отправленный текст. Повторно создавать уже подтверждённую задачу не нужно.
- **Повтор только явный.** Автоповтора и офлайн-очереди нет. Очередь быстрого добавления содержит только явно отправленные Enter записи и хранится в памяти страницы. Пока запрос в пути (waiting for server response) или его результат неизвестен (save result unknown), форма держит отправленные значения закрытыми. Повторять нужно предложенной кнопкой: **Retry**, **Retry original**, **Retry original save**, **Retry original dates**, **Retry original columns**. Найти исходную форму помогают **Resume original editor**, **Open original hours save** и **Resume column save**. Повтор отправляет то же содержимое с тем же ключом и дубля не создаёт. Не создавайте запись заново, пока не проверили, что уже сохранено на сервере.
- **Конфликт.** Если кто-то изменил данные раньше вас, черновик не перезаписывается: **Load latest version**, **Review changes** или **Reload and review**. Для личных колонок после конфликта **Discard changes** перечитывает текущие настройки, а ошибка закрытого окна показывает **Review columns**. **Reload and review** переносит черновик на новую версию только после подтверждённого конфликта; в остальных случаях он сохраняет исходную версию, а несохранённая или неподтверждённая запись не сбрасывается. Если доступа нет, сообщение нейтрально: оно не утверждает, сохранились ли настройки, — проверьте их после восстановления доступа ([64](64-personal-columns-recovery.md)).
- **Черновики живут только в памяти страницы.** При уходе спрашивается **Leave this page?**: **Stay** или **Leave without saving**. Перезагрузка, закрытие вкладки, смена пользователя и осознанный уход теряют черновик и ключ повтора.
- **После перезапуска API или обновления.** Если после перезапуска API список выдаёт ошибку, перезагрузите его. Старая вкладка после обновления показывает **Workloom has been updated** → **Refresh tab**, адрес сохраняется.
- **Если пишете о проблеме.** Укажите пользователя, представление, шаги, точные надписи и **Request ID:**, если он показан. Секреты и содержимое `.env` не прикладывать.
