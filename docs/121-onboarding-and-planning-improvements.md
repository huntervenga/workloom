## Что появилось

| Функция | Где найти | Что делает |
| --- | --- | --- |
| **Сумма подзадач у родителя** | Таблица проекта, колонки типа number и duration | Если у родителя в колонке пусто, а у подзадач есть значения, показывается их сумма серым курсивом. Вписанное вручную (в том числе `0`) всегда главнее и сумму отключает. Только отображение: в базу не пишется, итоги колонок и секций не меняются. Не показывается, пока загружены не все задачи проекта. Встроенная колонка «Team estimate» не затронута. |
| **Значения по умолчанию для новых задач** | Проект → **New task defaults** (владелец/администратор) | Статус, приоритет, оценка команды и значения обычных полей, с которыми стартует новая задача. Пустое поле = нет значения по умолчанию (например, Fact). Действует для таблицы, API и MCP; явное значение вызывающего всегда главнее; устаревшее значение (архивное/закрытое поле, удалённая опция) молча пропускается. Оценка команды ставится только задачам верхнего уровня. |
| **Копия проекта без задач** | Проект → **Create next copy** | Новый проект с секциями, полями и опциями, раскладкой колонок, итогами и сводками секций, проверками планирования, значениями по умолчанию, сохранёнными отчётами и настройкой work type. Идентификаторы переносятся, календарные диапазоны сдвигаются на заданное число дней (7 = следующая неделя). Имя предлагается автоматически: «42 week (since 19 October 2026)…» → «43 week (since 26 October 2026)…». Повтор с тем же ключом продолжает копию, а не создаёт второй проект; необязательные части при сбое дают предупреждение. |
| **Копирование проверок между проектами** | Проверки планирования → **Copy checks from another project…** | Правила переносятся в черновик по совпадению типа и названия поля/секции; для полей с другим названием можно выбрать пару вручную. Сохраняет человек. |
| **Импорт отсутствий из CSV** | Time off → People → **Import absences** (владелец/администратор) | Колонки Person, Type, Start, End, Note находятся по названию; неизвестные имена и типы сопоставляются вручную; уже записанные строки пропускаются; каждая строка — отдельное утверждённое отсутствие со своим ключом идемпотентности. Даты ISO или `06.07.2026`. |
| **Точность оценок по периодам** | Reports (workspace) → таблица **Estimation accuracy by period** | Actual ÷ Estimate по команде и каждому человеку за неделю/месяц, цветом по отклонению от 100% (до 10%, до 25%, больше), плюс тренд «промахи уменьшаются / растут / стабильно» — только при 4+ периодах с данными. |
| **Список первых шагов** | Overview рабочего пространства (владелец/администратор) | Пригласить команду, настроить рабочие часы и отпуска, добавить проект, подключить инструменты. Отмечает выполненное, скрывается, когда всё готово, или по крестику. |

## Защита от двойного учёта и «закрыть и продолжить» (добавлено позже в тот же день)

| Функция | Где найти | Что делает |
| --- | --- | --- |
| **Mark complete** | Панель задачи (внизу, рядом с Archive) | Кнопка как в Asana: завершить / «Completed» (клик — вернуть в работу). Рядом ▾ с пунктом **Complete and continue in another project…** |
| **Закрыть и продолжить в другом проекте** | Меню ▾ у Mark complete | Завершает задачу как есть (Fact остаётся на ней), создаёт в выбранном проекте задачу «Название 2» (следующий номер: 2→3…), ставит зависимость finish‑to‑start «старая блокирует новую». Переносятся только название, проект и исполнитель; остальное — значения по умолчанию проекта, без записанного времени. Сначала проверяется целевой проект, потом закрытие; повтор с тем же ключом продолжает, а не дублирует. Эндпоинт `POST /api/v1/workspaces/:ws/tasks/:id/continue`. |
| **Даты закрытых задач** | Над списком задач проекта с датами | Жёлтая плашка и подсветка даты: закрытая задача без срока (красным), со сроком до начала или после конца проекта (жёлтым). Открытая задача верхнего уровня без срока тоже красная: отчёты по периодам не смогут её учесть. |
| **Задача в двух проектах** | Панель задачи → Projects | Предупреждение: время и оценка считаются один раз, в проекте-доме и в периоде срока; для переноса работы использовать «Complete and continue…». |

Отчёты по периодам и раньше относят задачу одной канонической записью по сроку; задача без срока в когорты недель не попадает (`missingDateTasks`). Итоги колонок самого проекта по‑прежнему суммируют все его задачи.

## Границы и честные ограничения

- Сумма подзадач — подсказка в колонке, а не данные. Отчёты по-прежнему считают значения самих задач, поэтому двойного счёта нет.
- Копия проекта запускает обычные команды по шагам (структура, затем настройки). Это не одна транзакция: при обрыве повторите тот же запрос — он продолжит с места остановки. Не копируются: задачи, комментарии, история, личные настройки таблицы, шаблоны сводок (summary templates) и их привязки, периоды и политики полей.
- Статусы проекта фиксированы (To do / In progress / Done / Cancelled): копируется их привязка по названию.
- Точность оценок строится по **текущим** значениям задач с датой срока в периоде. Это не часы, отработанные в конкретную неделю, и не оценка качества работы. Нужны оба значения у задачи (оценка и факт), нулевая оценка не даёт процент.
- Импорт отсутствий не создаёт сотрудников, графики и типы отпусков: сначала настройте Time off. Исторические строки требуют причину; по умолчанию «Imported from spreadsheet».
- Значения по умолчанию не меняют существующие задачи и не применяются при импорте Asana, дублировании задач и копировании проекта (там переносятся реальные значения).
