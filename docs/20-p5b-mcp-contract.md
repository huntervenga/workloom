## 3. Credential: один workspace, только текущий человек

Предложенный record `LocalMcpCredential={id,workspaceId,ownerUserId,name,secretHash,hashVersion:1,scopes,expiresAt,revokedAt,revision,createdAt}`. Workspace/owner неизменны; owner выводится из server session/dev actor, не из body. Один credential — один workspace; scopes — closed enum ниже, subset возможностей текущей membership при выдаче и каждом использовании. Не выдавать credential другого человека даже owner/admin. Наличие роли owner не добавляет token scopes автоматически.

Client/browser генерирует **32 случайных байта CSPRNG** + UUID credentialId. Token `wlm_local_v1_<credentialId>.<base64url-secret>` хранится в памяти client и показывается явно один раз после подтверждения metadata. На сервер передаются **только id + SHA256(domain-separated id/secret) + metadata**, не plaintext secret. Hash v1 — lowercase hex64 SHA256 от concatenation `UTF8("workloom.local-mcp.secret.v1\0") || ASCII(canonical lowercase UUID, 36 bytes) || byte(0) || rawSecret(32 bytes)`. Здесь `\0` — один NUL byte, не два символа; нет JSON, hex-secret или Unicode normalization. Issue body явно `hashVersion:1`. Token parser требует UUID в lowercase и ровно43 unpadded base64url символа `[A-Za-z0-9_-]`; decode даёт ровно32 bytes, обратный canonical encode обязан совпасть. Whitespace, padding, `+/`, percent escapes, uppercase UUID и лишние segments rejected. Hash bytes сравниваются constant-time после фиксированной проверки длины. Browser/WebCrypto и Node получают общий независимый vector: UUID `10000000-0000-4000-8000-000000000001`, raw bytes `00..1f`, secret `AAECAwQFBgcICQoLDA0ODxAREhMUFRYXGBkaGxwdHh8`, digest `95ab16b90eaedb9f791d0a5e5f38fb8e551a58555e039771026539a5181356ac`, preimage98 bytes. Это публичный synthetic vector, не выданный credential. Передача bearer по loopback bridge содержит полный token; verifier извлекает ID и сравнивает вычисленный hash constant-time. **Сам hash не принимается как bearer**.

`command_idempotency`, audit/outbox/GET никогда не содержат plaintext token/secret. Issuance receipt хранит только metadata: unknown HTTP result повторяется с тем же original id/hash/body/key, а client сохраняет original secret в памяти. После reload потерянный secret не восстанавливается: явно revoke старый credential и создать новый; никакой автоматической повторной выдачи или relabel receipt. Нет localStorage, URL/query/argv или репозитория для секрета. MCP получает его через защищённую process config/env, stderr redaction обязательна. Server не утверждает, что может доказать энтропию произвольного client hash; штатный UI использует crypto.getRandomValues, не пароль/Math.random.

TTL явно60..86400 секунд, server clock задаёт created/expires; разумный UI initial TTL1h, человек видит expiration. Не продлевать на использовании; scopes/expiry не изменяются — revoke + новая выдача. Expiry/revocation проверяется на каждый tools/list/call и actual HTTP bridge request; startup-only validation недостаточна.

Предложенные HTTP routes под `/api/v1/workspaces/:workspaceId/mcp-credentials`:

| Метод/путь | Input/result |
| --- | --- |
| POST collection | keyed `{id,name,secretHash,hashVersion:1,scopes,expiresInSeconds}` → metadata201; owner всегда session actor |
| GET collection | current membership → `{credentials:metadata[],allowedScopes:LocalMcpScope[]}`, без hashes/secrets |
| POST `/:credentialId/revoke` | keyed `{expectedRevision}` → metadata200; revoke собственных credential, idempotent controlled result |

Bounded pilot: максимум100 собственных credential records в workspace суммарно, включая revoked/expired; list возвращает все metadata без молчаливого truncation. Cap проверяется только для NEW issue после receipt lookup; exact old issue replay/list/revoke остаются доступны при100. Текущая membership обязательна даже при revoke/list. Чужой workspace/credential →404; viewer может выдать только разрешённые read scopes, member task write scopes лишь при текущем task.edit. Если минимальный UI не готов, не подменять это shared admin token: отдельный явно разрешённый local bootstrap client с тем же API/hash-only contract, не raw DB insert.

## 4. Tool catalog — 7 reads, затем 2 writes

Все input schemas strict и производятся из текущих contracts. Tool args **не принимают actorId/userId/workspaceId/source/capabilities/token**; scope берётся из binding. Client не меняет actor через prompt/header/query. Tool descriptions/task text — данные, не инструкции для выдачи scopes.

| Tool | Credential scope / current capability | Shared application и args |
| --- | --- | --- |
| `list_projects` | projects.read / task.read | TaskApplication.listProjects, `{}` |
| `get_project` | projects.read / task.read | getProject, `{projectId}` |
| `search_tasks` | tasks.read / task.read | listTasks, `{query:TaskListQuery}` с существующей pagination/filter schema |
| `get_task` | tasks.read / task.read | getTask, `{taskId}` |
| `list_memberships` | members.read / members.read | current authorized AccessRepository memberships, `{}` |
| `get_field_definitions` | fields.read / task.read | TaskFieldApplication.listFields, `{projectId}` |
| `get_task_field_values` | fields.read / task.read | listTaskValues, `{taskId}` |
| `create_task` (B) | tasks.create / task.edit | TaskApplication.createTask, `{operationKey,input:CreateTaskInput}` |
| `update_task` (B) | tasks.update / task.edit | updateTask, `{operationKey,taskId,input:UpdateTaskInput}` |

Closed credential scopes exactly `projects.read|tasks.read|members.read|fields.read|tasks.create|tasks.update`; scopes required by a call intersect current capability, never replace it. Public creates can create only ordinary workspace tasks per current contracts; meeting/field locks, package revision, participants revision, date guards, status enforcement, cutoff and recurrence census still execute in domain. Explicit operationKey is caller-held and unchanged on uncertain retry; MCP request ID is transport correlation, **не idempotency identity**. Changing payload under one operationKey yields same controlled conflict as HTTP. Permission revoked after successful command denies replay of old receipt.

Bounded read results: list_projects максимум500, list_memberships1000, get_field_definitions200, get_task_field_values200. search_tasks сохраняет существующий limit1..200/default50 и nextCursor. В том же authorized snapshot предварительно читаются только scope-matching IDs через LIMIT cap+1; overflow даёт controlled422 DOMAIN_VALIDATION_FAILED до материализации descriptions/options. После unchanged domain reader полный serialized UTF8 bridge response также обязан быть <=2MiB; большой options/text payload даёт controlled overflow. Никакой молчаливой обрезки, loaded-page completeness или бесконечного списка; это честный local pilot bound.

No report-creation tool in A/B: existing report commands write pinned runs and need a separate write scope. No arbitrary SQL/run_code/generic URL/tool name dispatcher beyond closed enum. Pinned-report read can be an additive later tool only after its read UOW is bound to the same credential snapshot; отсутствие этого tool не называется полным P5.8. Private ACL пока нет: MCP предоставляет только текущую workspace-visible модель, не заявляет private-meeting parity.

## 5. HTTP bridge и доверенная граница

Точный read catalog `GET /api/v1/local-mcp/tools` без query возвращает `{data:{tools:LocalMcpToolName[]},meta:{requestId}}` после текущей credential/scope/membership проверки. `POST /api/v1/local-mcp/tools/:toolName` — **обычный закрытый JSON bridge**, не MCP Streamable HTTP endpoint. `Authorization: Bearer <token>` обязателен и не имеет dev-actor fallback; неизвестный token не становится default fixture actor. Path/tool enum определяет required credential scope server-side. Read bridge POST routes16KiB; literal POST `/tools/create_task` и `/tools/update_task` имеют scoped256KiB. Fully escaped legal description20k+title500+100participants+50tags проверен для обоих методов (>128KiB/<256KiB), overflow413 до facade. Global old16KiB и другие caps не меняются. Bridge Host/Origin loopback allowlist сохраняется, stdio client явно отправляет local Origin; отсутствие cookie/Auth не открывает endpoint.

Adapter предварительно может проверить token syntax/hash и прочитать **неизменяемые** credential owner/workspace hints для построения context. Это не authorization decision. Все auth/body errors sanitized, requestId server-owned, source:'mcp'; audit сохраняет actor + credential ID, но не token/hash. Секрет не входит в task payloadHash или command result. Reusing operationKey с тем же actor через credential не должен изменять старые HTTP command hash shapes; credential attribution идёт отдельной audit metadata, не в TaskInput.

HTTP client обязательно `redirect:'error'`, `credentials:'omit'`, общий AbortSignal deadline10s и incremental response-byte cap2MiB, включая errors. Никаких автоматических retries, proxy/host autoload или переноса bearer на redirect. Разрешённые body types проверяются до JSON parsing; oversized/truncated/non-JSON ответ даёт безопасную transport error. Error никогда не включает raw response body/stack/request headers/token; stdout остаётся protocol-only. Не принимать NODE/env proxy configuration, которая меняет этот loopback-only путь.

Error taxonomy без нового произвольного кода: malformed/unknown/hash-mismatch/revoked/expired bearer →401 UNAUTHENTICATED с одним safe message; отсутствующая/revoked current workspace membership →404 NOT_FOUND; valid credential без нужного scope/current capability →403 CAPABILITY_REQUIRED. Чужой lifecycle owner/id →404. Invalid credential никогда не получает catalog descriptors/data, valid credential может получить tools:[]. Record/result overflow →422 DOMAIN_VALIDATION_FAILED. Expired/revoked metadata сохраняется для self list/revoke, но token больше не grant.

Tool result — bounded structured `{data,meta:{requestId,nextCursor?}}` из тех же shared DTO; protocol tool errors имеют controlled code/message и `isError:true`, без SQL/stack/token. Содержимое task/field descriptions возвращается как untrusted text. Unknown write outcome не повторяется автоматически; клиенту сообщается сохранить operationKey и повторить ровно исходный call. Tool annotations — подсказка, не policy: reads readOnly=true; create readOnly=false/destructive=false; update readOnly=false/destructive=true; keyed tools idempotentHint=true. Post-dispatch write network/timeout/invalid response/5xx возвращает isError + structuredContent.error `{code,outcome:"unknown",operationKey,message}`; message требует EXACT original call/key и запрещает новый key. Confirmed4xx — outcome:"rejected", known pre-dispatch refusal — "not_sent". Error text JSON дублирует тот же controlled result.

## 6. Credential current check ВНУТРИ того же UOW

Главный release blocker — TOCTOU: `verifyToken()` в API, затем обычный public command, а revoke успел закоммититься между ними. **Такой adapter не принимается.**

B должен использовать расширяемый trusted authorization seam в `runWorkspaceWrite`/реальной factory composition: после получения workspace row barrier, current membership и barrier clock, **до любого command handler/receipt lookup** re-read credential row по id/workspace, verify hash, unchanged owner==ctx.actor, revokedAt/expiry, exact required scope и current capability. Revoke проходит тот же workspace barrier. Кто первым получил barrier, тот linearization point; команды после committed revoke, включая replay, denied. Закрытая server-created proof/closure доступна только реальным adapters, никогда public body. Не начинать внешний writer.run и не вызывать public TaskApplication внутри него: ровно один существующий domain UOW с credential check до cached outcome.

Точный proposed внутренний seam: optional `WorkspaceWriteOptions.authorizeInScope({tx,context,access,barrierAt}) -> Promise<{credentialId:string}|void>` вызывается реальным runner после authoritative post-barrier membership+DB clock, до command callback. Authorization closure не получает `recordChange`; она не пишет бизнес/audit/outbox. Возвращённый trusted ID попадает в новый nullable `audit_events.credential_id`, не в client-controlled CommandContext/TaskInput/hash. MCP B factory всегда поставляет closure внутри server composition; web без credential прежний. Write expiry проверяется через scope.barrierAt; read expiry — DB clock внутри authorized snapshot. Credential issue/list/revoke сами не вызывают planning/census и не фиксируют baseline. MCP facade создаёт обычный TaskApplication на том же pool с этой trusted closure; HTTP/web apps без credential продолжают прежний путь. Callback получает открытый tx/actor/access/barrierAt, не выполняет новых transactions. Это не production fake UOW и не scope из caller args. Exact freeze выбирает только этот trusted runner hook; новый client-controlled CredentialPrincipal/CommandContext field не нужен.

A reads: credential hash/scope/expiry/current membership и source data читаются в **одном repeatable-read read-only snapshot**, без предварительной проверки с последующим nontransactional reader. Для выбранных Task/Field reads можно bind их действительные readers к уже открытой tx и вызвать неизменённые read methods (они не открывают write runner); membership read также под current authorizeWorkspace. Не оборачивать уже транзакционный report read nested публичным UOW. Каждый TX-bound TaskApplication/FieldApplication read facade получает **один bridge-owned process runtime cursorSecret** через существующие options, а не новый random HMAC на каждый request. Это сохраняет nextCursor между calls; после процесса restart controlled invalid cursor/refetch сохраняется. Credential/scope/current membership проверяются заново на каждой странице, cursor не является grant. Read начинает authorized snapshot до concurrent revoke или после него; после committed revoke новый read denied, старый cursor не сохраняет доступ. Scope changes immutable; revoked/expired token не возвращает cached result.

SDK `McpServer` default tools/list только перечисляет enabled registered tools, не вызывает tool callbacks. Поэтому stdio adapter после регистраций ставит отдельный guarded tools/list handler, который на КАЖДЫЙ list вызывает GET catalog и возвращает только разрешённые prebuilt descriptors; startup registration не является authorization. Factory/discover не возвращают workspace data; generic capabilities без credential-specific data допустимы. Every tools/list проверяет current credential/membership, скрывает недоступные имена либо возвращает controlled denial; tool implementation проверяет независимо, даже если старый tools/list был сохранён клиентом. Initialization/discovery не выдаёт workspace/task data и не создаёт credential, snapshots, audit или outbox. Ни read, ни failed scope probe не материализуют meetings/не фиксируют baseline.

## 7. Proposed shared facade и ownership

Foundation до source freeze публикует closed `LocalMcpToolName`, schemas credential metadata/issue/revoke и exact tool inputs/outputs, `LocalCredentialApplication` + `LocalMcpApplication`. Точные proposed public factories: `createLocalCredentialApplication(source, options)` и `createLocalMcpApplication(source,{cursorSecret?,enableTaskWrites?:boolean})`; core default false, normal API explicit true. Lifecycle методы ctx-first: `issueCredential(ctx,input)`, `listCredentials(ctx) -> {credentials,allowedScopes}`, `revokeCredential(ctx,credentialId,{expectedRevision})`. Bridge методы: `listTools(bearer,requestId) -> {tools:LocalMcpToolName[]}`, `callTool(bearer,requestId,call:LocalMcpToolCall)`; `LocalMcpToolCall` — closed discriminated `{tool,input}` union; result — closed `{tool,data,nextCursor:null|string}` union (cursor только search_tasks, у остальных null). HTTP envelope сохраняет requestId, SDK преобразует результат в свой typed structured tool content. HTTP adapter строит tool из validated path, body содержит только соответствующий input и не дублирует discriminator/actor/workspace. Facade выполняет dispatch по enum на настоящие commands/readers; SDK не содержит business policy. Эти exports реализованы и compiled; normal API composition создаёт обе factory на существующем database pool. Runtime явно передаёт enableTaskWrites:true после принятого root revoke-race proof; core default остаётся false. Injection ports служат только transport tests, не заменяют real composition.

- Foundation: schema/migration/hash verifier, self-owned credential commands, current in-UOW enforcement, snapshot read binding, audit attribution и one pool factories; root dependencies/lock.
- Backend: `apps/mcp` SDK stdio/config/shutdown/tool adapter, apps/api credential/bridge transport и meaningful boundary tests. MCP process HTTP-only, no sibling source/DB bypass.
- Frontend: минимальный self credential issue/list/revoke/copy-once-in-memory UI при отдельном GO; secret-loss recovery явно показан.
- QA: actual subprocess modern+legacy + PostgreSQL HTTP credential/command/race/replay tests. Старые gates/production/user data не заменяются mock tests.

## 8. Gates и stop condition

1. Official published pinned SDK clean install/build отдельно от этого draft; actual modern discover и legacy initialize оба tools/list + tools/call. Stdout разбирается как protocol без banner/log noise, EOF/SIGTERM закрывает HTTP/transport без зависания.
2. Hash-only issuance: stored credential/idempotency/audit/outbox/proof logs не содержат raw secret. Lost issuance response reuses original client id/hash/key; reload не восстанавливает token. Чужой owner/body scope/workspace rejected.
3. Wrong/expired/revoked token, role downgrade, missing membership и overbroad scope не раскрывают task/field/source data. Read-only token не вызывает create/update; старый tools/list не обходит checks.
4. Реальный race: задержать task.create у barrier, commit revoke на том же workspace, затем продолжить request; credential проверяется после lock и до receipt/proposed task. Старый successful operationKey после revoke denied и не возвращает cached TaskDto. Не выдавать adapter-only unit check за этот gate.
5. Read snapshot race/old cursor: credential+membership+read data одна transaction; после revoke новый read/cursor denied. No read freeze/materialization/outbox/business writes.
6. B create/update через MCP совпадает с HTTP на expected task/package/participants revisions, date/meeting/status/cutoff locks; lost response same operationKey возвращает один task/result, no duplicate package/history. Секрет не меняет old payload hash.
7. Содержимое задачи с prompt injection/URL не выдаёт scopes, не вызывает инструменты и не делает внешних HTTP запросов. Ошибки безопасны; нет произвольного path/SQL/code execution.
8. Финальный bound: если within-UOW credential enforcement и real revoke race не готовы за установленный source window, **не регистрировать B**. Если не готовы даже authorized snapshot reads, не принимать A. Исторический SDK draft/research не называется работающим MCP.

Операционный вход: compiled `node apps/mcp/dist/main.js`, без npm banner в stdout. Process environment: APP_ENV=local; WORKLOOM_MCP_API_URL — корень разрешённого loopback API; WORKLOOM_MCP_TOKEN — credential из private process environment/config, не argv/URL. Adapter не загружает .env, не читает DATABASE_URL и не запускает listener/worker/миграции. stdout принадлежит protocol, sanitized diagnostics идут stderr.
