## Порядок и назначение

В **Group by → Assignee** обычные активные задачи показаны плоским списком: корневая задача и подзадача могут стоять рядом независимо от родителей. В **Sort → Manual** ручка слева от названия начинает перенос. Перенос внутри группы меняет порядок; перенос в другую группу меняет ответственного и место. **Unassigned** означает явное отсутствие ответственного. Доступна и пустая группа активного участника.

Перенос подзадачи в другой персональный список **сохраняет её parent, section, work package, участников, оценки, план и факты**. Это не переподчинение и не новый объём работ. Section-группировка сохраняет собственные ограничения: подзадача остаётся среди своих siblings; обычная корневая задача может перейти в section цели. При сортировке по сроку drag не предлагается: пользователь явно переключает **Manual**, сортировка сама не меняется.

Во время drag видна карточка задачи и линия допустимой вставки; удержание у вертикального края прокручивает список. Escape отменяет перенос. Окончательный порядок приходит от сервера. Сервер использует полный порядок проекта, включая скрытые, архивные и ещё не загруженные строки, и сохраняет относительный порядок остальных задач. Drop после группы использует её полный серверный список. Если группа пуста или задача уже стоит после её последнего участника, сохраняется исходное глобальное место: переназначение само не переносит задачу в конец проекта. При изменении только ответственного сохраняются числовые positions, включая ties и gaps. Настоящий no-op не меняет task revision и audit; idempotency receipt и cutoff сохраняют обычный протокол. Архивные задачи, неподходящие sections и недоступные участники не становятся допустимыми целями. Встречи сохраняют отдельные schedule/roster guards; обычный task editor не редактирует их даты.

## Выделение и одна атомарная команда

Левая область строки выделяет задачу без редактирования названия. Обычный click выбирает одну строку; **Shift-click** выбирает видимый диапазон, **Ctrl/Cmd-click** добавляет или убирает отдельные строки. Скрытые и свёрнутые строки не добавляются в диапазон автоматически. Лимит — **100 задач**; скрытое текущее выделение показывается отдельно и может быть явно снято.

Панель **Edit selected tasks** позволяет выбрать Assignee и/или даты, затем явно нажать **Apply to selected tasks**. Запрос содержит 1–100 уникальных task IDs с увиденными revisions. Отсутствующее поле не меняется; явный **Clear** передаёт `null` только выбранному endpoint. Открытие пустого или mixed date editor само ничего не очищает. Для каждого выбранного task проверяется итоговый диапазон с учётом его сохранённых дат.

Сервер применяет весь пакет одной транзакцией. Один устаревший revision, недоступный task, неверный диапазон или запрещённая встреча отклоняет весь пакет. На replay заново проверяются права на **каждую** выбранную задачу. Unknown outcome сохраняет исходные body и ключ; **Retry original** повторяет их точно, без автоматического повторения и без замены задач новым выделением. Исторические baseline, work logs и package identity не переписываются.

## Due date и необязательное начало

Редактор **Edit dates** сначала показывает **Due date**. Кнопка **+ Start date** раскрывает начало и конец; уже сохранённое начало видно сразу и не теряется. Открытие начала не подставляет дату. Общий компактный календарь работает с активным endpoint, форматирует месяц и дни текущей локалью, поддерживает Previous/Next month, стрелки, явные Today и Clear. В task details тот же календарь открывается при фокусе даты, не увеличивая постоянную высоту формы.

В текстовых полях неполное `YYYY-MM-DD` сохраняется как введено и не становится командой очистки. Значения остаются календарными `YYYY-MM-DD`, годы **0001–9999**; начало и конец могут отсутствовать. Даты не преобразуются в timezone instants. Перед сохранением проверяется окончательное `start ≤ due`; обратный диапазон не отправляется. Оба изменённых endpoint уходят одной существующей task update командой с revision. При unknown они заблокированы и повторяются исходным запросом. В новой строке даты остаются локальным draft до отправки строки; первый Escape закрывает её date/tag picker и возвращает фокус, сохраняя ввод. Сохранённый диапазон использует существующую модель [Timeline/Gantt](72-gantt-date-move.md); resize и automatic scheduling не добавлены.

## Tags и настоящий факт

Сохранённая ячейка **Tags** теперь открывает **Edit tags**: поиск и выбор существующих workspace tags, цветные метки, явное сохранение. Enter в поиске не отправляет форму. Retained archived/missing tags остаются узнаваемыми и удаляемыми; архивные теги не предлагаются как новые назначения. Изменение tags не меняет estimate, даты или часы.

Если тегов нет, **Open details to create tags** ведёт в существующую форму, сохраняя task draft. В task details доступен **New tag → Create tag**; управление общим каталогом также доступно через действия проекта **Tags → Workspace tags**. Для новой строки handoff предлагается только когда существующий guard может безопасно передать её draft. Произвольное создание тегов внутри cell picker не заявлено.

**Weekly actual hours** и план доступны в стандартном наборе колонок до выбора недели; вместо выдуманного нуля показан **Choose week**. Эта кнопка открывает существующий **Week for hours**. Пользователь видит конкретную неделю и **Whose hours to show**; никакая неделя не выбирается автоматически. Ранее сохранённое скрытие колонки уважается. Contextless часы не предлагают переход к фоновому picker из modal subtask table. Estimate/Team estimate остаются общей оценкой пакета; факт — отдельная запись для явных week/person. Missing, void и сохранённый `0` различаются; totals берутся из серверной проекции, без суммирования загруженных подзадач. См. [модель plan/fact](14-p2b-contract.md).

Редактор должен сохранять draft и позицию строки при refresh и смене группировки. Late ACK и повторный render не должны заново забирать фокус или прокручивать страницу к прежнему редактору. Горизонтальный reveal ограничен собственной таблицей; приёмка отсутствия скачка проверяется отдельно в compiled Chrome.
