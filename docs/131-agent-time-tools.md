# 131 · Поля и время через публичный API и MCP (для агента)

**Зачем.** Чтобы задачи и часы можно было вести, просто написав агенту (Claude или Codex): "добавь задачи на неделю", "заполни факт за неделю до нормы". Время в командных проектах лежит в двух обычных полях длительности, `Estimation` (план) и `Fact` (факт); на каждую неделю обычно свой проект с диапазоном дат. Норма человека - его рабочий график (40 ч полная ставка, меньше для неполной) минус праздники и отпуска, это уже считает Time off.

Это шаг 1. Шаг 2 - вход через OAuth для claude.ai и телефона - описан в [132](132-oauth-connected-apps.md).

## Что добавлено

| REST (`/api/public/v1`) | MCP | Доступ |
| --- | --- | --- |
| `GET /workspaces/{ws}/projects/{project}/fields` | `list_fields` | read |
| `GET /workspaces/{ws}/tasks/{taskId}?includeFields=true` | `get_task` (поля всегда) | read |
| `GET /workspaces/{ws}/tasks?includeFields=true` | `list_tasks` с `includeFields` | read |
| `POST /workspaces/{ws}/task-fields` | `set_task_fields` | tasks:write (+ `task.edit` роли) |
| `GET /workspaces/{ws}/projects/{project}/time-summary` | `time_summary` | read |
| `POST /workspaces/{ws}/tasks/{taskId}/projects` | `add_task_to_project` | tasks:write (+ `task.edit` роли) |

- **Значения по имени.** Поле - точное имя без учета регистра или UUID. Длительность - целые минуты или текст `90m`, `1.5h`, `1h 30m`, `1:30` (понимает и `ч`/`мин`). Варианты выбора и люди - по имени, `null` очищает. Неизвестное или неоднозначное имя, неверный формат, заблокированное поле - это `failed` у конкретного изменения, остальные изменения запроса продолжаются.
- **`dryRun`.** Возвращает каждое изменение с `before`/`after` и ничего не пишет. Инструкции MCP требуют от агента сначала показать такой план и дождаться подтверждения.
- **Запись.** Каждое значение - отдельная доменная команда `setTaskValue` (блокировки, политики полей, история значений, аудит, outbox как при правке в таблице; источник `api`). Запрос в целом не атомарен: смотреть `summary.failed`.
- **Повтор.** Ключ (`Idempotency-Key` / `operationKey`) привязан к телу запроса. Разрешенный план (поля, ожидаемые ревизии, типизированные значения) закрепляется под ключом до первой записи, поэтому повтор после сбоя выполняет те же команды с производными ключами и они воспроизводят свои квитанции. Тот же ключ с другим телом - `IDEMPOTENCY_KEY_REUSED`.
- **Токен.** Запись перепроверяет токен под барьером workspace (`tokenInScope`, общий с правкой задач); отзыв, закоммиченный раньше, побеждает.
- **`add_task_to_project`.** Показывает готовую задачу ещё в одном проекте (размещение), например задачу из бэклога в проекте недели; проект и раздел - по имени или UUID. Домашний проект, часы и значения полей задачи не меняются. Внутри - доменные команды размещений веб-клиента (`attachTaskProject`, `restoreTaskProjectPlacement`, `updateTaskProjectPlacement`) со всеми их проверками; токен перепроверяется под барьером, как у остальных записей. Задача уже в проекте (домашнем или размещённом) - ответ `unchanged` без записи, поэтому повтор безопасен; снятое раньше размещение восстанавливается (`restored`), раздел применяется только при добавлении или восстановлении.
- **`time_summary`.** Строки проекта берутся по размещениям (`listProjectRows`), то есть вместе с общими задачами из других проектов; значения - поля этого проекта. Время принадлежит исполнителю задачи; подзадача без своего исполнителя считается за ближайшим родителем с исполнителем, как в Reports (явный исполнитель подзадачи не меняется). Каждая задача считается своими сохраненными значениями; сворачивание подзадач в родителя в таблице - только отображение и второй раз не прибавляется. Диапазон - даты проекта или `from`/`to`. `expectedMinutes` = `availableMinutes` из Time off; без графика человека или без настроек Time off - `null` и пояснение в `notes`. Не больше 2000 задач и 100 человек.
- **Инструкции сервера.** `initialize` у `/mcp` возвращает `instructions`: где лежит время, что неделя - отдельный проект, как набирать факт до нормы (кратно 15 минутам, чужие задачи не трогать без просьбы) и что перед записью нужен `dryRun` и подтверждение.

Миграций нет. Файлы: `packages/contracts/src/automation.ts`, `packages/db/src/automation/{fields,service}.ts`, `apps/api/src/http/{public-api-routes,public-api-openapi,mcp-http}.ts`, `apps/web/docs.html`.

## Как подключить сейчас (Claude Code)

1. Integrations → создать токен со scope `read` и `tasks:write`.
2. `claude mcp add --transport http workloom https://<workloom>/mcp --header "Authorization: Bearer $WORKLOOM_TOKEN"`.
3. Написать, например: "заполни мой Fact за неделю 45 до нормы, сначала покажи план".
