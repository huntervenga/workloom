# 129 · Перенос задачи в другой проект (смена домашнего проекта)

**Что это.** `POST /api/v1/workspaces/:ws/tasks/:taskId/transfer-project` `{expectedRevision, projectId, sectionId?}` делает проект назначения домашним для задачи и всех её подзадач. Интерфейс: панель задачи → поле «Проекты»: выпадающий список с текущим проектом; выбор другого проекта переносит задачу сразу, рядом показывается итог (что поехало, что осталось) и кнопка «Move back to …». Подзадачу отдельно перенести нельзя (двигается родитель).

**Что меняется.** `tasks.project_id`, пакеты работ, статус (по имени в той же группе, иначе первый статус группы), секция (по имени, либо выбранная для самой задачи), позиция в конце проекта. Значения пользовательских полей копируются в поля цели с тем же именем и типом (варианты выбора — по названию); остальное остаётся у отцепленного размещения старого проекта и в отчёте помечается как `notCarried`. Часы, планы и отчёты с этого момента считаются в новом проекте и перестают считаться в старом; сохранённые отчёты и базовые линии не переписываются.

**Правила проекта.** Две независимые галочки: «одна задача — один проект» (`singleProject`, как раньше, запрещает только добавление в несколько проектов) и новая «нельзя переносить из/в проект» (`lockMoves`). Перенос под `singleProject` разрешён.

**Что остаётся неизменным.** История значений полей и ссылки импорта Asana не переписываются. Прежний домашний размещение остаётся отцепленным (нужно, чтобы иммутабельная история значений сохраняла опору), повторный перенос в прежний проект его оживляет.

**Когда отказывает (код причины → текст в интерфейсе).** Архивные задача/проект, подзадача, тот же проект, `lockMoves` на любой из сторон, более 500 задач в поддереве, запланированные часы, учтённая работа, замороженный план/базовая линия, встреча или серия, пакет работ, общий с неперемещаемыми задачами или разделённый. Ничего при отказе не меняется.

**Миграция 0037** (применяется отдельно, как 0029): заменяет внешний ключ ссылок импорта на `(workspace_id, task_id)`; делает первичный ключ размещений откладываемым (`DEFERRABLE INITIALLY IMMEDIATE`); разрешает охраннику идентичности размещений менять `id`/`home_project_id` только внутри транзакции переноса (`workloom.task_transfer = on`). Корректность домашних строк команда проверяет сама до коммита.

**Проверки.** Домен 16 тестов (3 новых), маршрут API 8, UI выпадающего списка 3 + правила 2, `tsc`, eslint, локализация. На копии реальной базы (отдельная схема, затем удалена): перенос Backlog → неделя 30 с подзадачей и значением поля, повтор с тем же ключом, цепочка неделя → неделя, возврат в Backlog, явная секция, отказ при устаревшей ревизии и при подзадаче; история значений (3442) и ссылки импорта (1967) неизменны. Интеграционный тест на тестовом кластере PostgreSQL не запускался (хелпер отказывается: `MAIN_PROCESS_IDENTITY_CHANGED`). Повторный импорт Asana уже перенесённых задач не проверялся: ссылки остаются за проектом, в который их импортировали.
