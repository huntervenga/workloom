# 130 · Защита выкладки (после падения прода 3 ноября 2026)

**Что случилось.** Пуш в `main` (его собирает и выкладывает Railway) два раза подряд уронил прод примерно на 12 минут. Причины: (1) миграция 0037 удаляла внешний ключ, которого на проде нет (прод-база загружена без внешних ключей и триггеров: 3 ключа вместо 209, 63 триггера вместо 130), ошибка `42704`; (2) `Dockerfile` копирует в образ явный список скриптов, а новый скрипт импорта в нём не значился, и старт падал с пустым «Error».

**Что теперь проверяется до пуша** (`npm run predeploy`, запускается хуком `.githooks/pre-push` при пуше в `main`; включить хук после клонирования: `npm run hooks:install`; пропустить: `SKIP_PREDEPLOY=1 git push`):
- `check-deploy-image`: каждый скрипт, который запускает или грузит рантайм (pre-deploy и всё, что API называет в `scripts/`), и все его импорты на любую глубину есть в `COPY` образа. На коммите, который упал, проверка называет недостающий файл.
- `check-migration-safety`: начиная с миграции 0038 любой `DROP` констрейнта, триггера, индекса, функции, типа, колонки или таблицы должен быть с `IF EXISTS` или внутри `DO`-блока с проверкой существования. 0037 уже применена на проде, её хэш менять нельзя.
- границы пакетов, локализация, типы, ESLint по исходникам, тесты этих проверок.

**После выкладки:** `npm run smoke:prod` ждёт до 6 минут ответа новой версии и проверяет `/healthz/ready` (база и схема ok), `/app`, наличие веб-бандла и `401` на анонимный `/api/v1/me`; код выхода не нулевой, если что-то не так.

**Если прод упал.** Откатить отдельный деплой в Railway из CLI нельзя. Быстрее всего: `git revert` последних коммитов и пуш (сборка около 3 минут). Если в ревёртнутом диапазоне есть миграция, оставьте её файл и запись в `_journal.json`: прод уже применил её, и приложение не стартует, если в журнале БД есть миграция, которой нет в файлах.

**Решения, которые остаются за владельцем** (не сделаны, нужны ваши доступы или согласие):
1. **Staging-окружение** в Railway (копия прод-схемы и данных): выкладка сначала туда, прод после зелёного дымового теста. Требует создать окружение и базу.
2. **Автодеплой из `main`.** Сейчас каждый пуш выкладывается сразу. Можно выключить автодеплой и выкладывать осознанно (`railway up` или кнопка) после `predeploy` и на staging.
3. **Расхождение прод-схемы.** В проде нет внешних ключей и почти нет триггеров. Из-за этого постоянное удаление проекта (идёт по обходу внешних ключей) в проде отказывает намеренно, а целостность держится только на коде. Восстановление ключей требует проверки данных на сироты и окна обслуживания.
