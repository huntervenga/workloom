# Связанные сводки секций и персональное время общих активностей

**Реализация в исходниках, общая приёмка ещё НЕ ВЫПОЛНЕНА.** Документ описывает текущий код следующего среза. Это не утверждение о работающем main, применённых миграциях или production. Последний принятый локальный срез остаётся в [103](103-refresh-duplication-and-person-reports.md). [102](102-shared-activities-and-summary-templates.md) сохраняется как историческое предложение: его текст не является доказательством реализации или проверки.

План и факт остаются обычными пользовательскими `duration`-полями, выбранными по ID. Их названия не имеют системного значения. Обязательной недели нет. Связанная сводка и общий созвон — два независимых инструмента; для подсчёта личного времени не нужно дублировать задачу каждому участнику.

## Настроить сводку один раз

1. Откройте **Summary** нужной секции. Настройте показатели, затем **Save as template**: укажите имя, проверьте текущую форму и сохраните. Сохранение создаёт шаблон и связь с этой группой; отдельное промежуточное Add не требуется.
2. В другой секции: **Use template → шаблон → Person → Apply linked template**. Person нужен для персонального времени, Available и соответствующих правил. У произвольной секции выберите человека явно; в группировке Assignee доступен **Person of this assignee group**. Название секции не назначает человека.
3. Проверьте **Tasks included**. **Tasks in this section or group** считает задачи группы. **This person's work across this project** (`selected_person_project`) выбирает работу человека в проекте, включая его участие в общих активностях. Выбор человека только для Available сам по себе не меняет область задач.
4. **Available and check target period**: Project dates, This week либо Custom dates. Это период доступного времени/целей проверок; не скрытый обязательный недельный фильтр всех задач. Для отбора самих задач служат явно настроенные scope/filters/cohort. Без дат проекта Project dates не изобретает диапазон.

Доступны обычные операции Sum/Avg/Min/Max/Count, **Personal effort including shared participation** для duration-поля и **Person's Available time**. Ручной target отмечается как локальное переопределение отображения; он не меняет расписание, отпуска или сохранённую доступность человека. Правила нагрузки и их пороги/цвета остаются настройками пользователя.

### Изменить всем или только одной секции

| Действие | Результат |
| --- | --- |
| **Edit template for all** | Новая версия общего шаблона применяется ко всем связанным группам; перед сохранением видно их количество. |
| **Customize this section** | Явные локальные исключения для существующих показателей/проверок по стабильным keys/IDs, а также Person/scope/period. Локальные изменения заметны и сохраняются при общей правке. |
| **Reset to template** | Убирает локальные overrides; связь и явно выбранный Person сохраняются. |
| **Detach from template** | Разрывает связь, оставляя разрешённые текущие конкретные настройки самостоятельными. |

Добавлять и удалять показатели/проверки нужно в общем шаблоне; локальная настройка заменяет существующие элементы по ключу. Ссылка действует внутри проекта: IDs полей не переносятся автоматически в другой проект. Есть пределы: 100 шаблонов и 100 связанных сводок на проект, до четырёх показателей и 50 balance checks в шаблоне; общие ограничения настроек также сохраняются.

При **Duplicate section**, если копируются связанные настройки, выберите явно **Keep template link** (`keep_link`) либо **Create independent settings** (`independent`, исходный выбор интерфейса). Первый вариант сохраняет будущие общие обновления; второй создаёт независимые разрешённые настройки. Person и периоды остаются буквально выбранными: переименование копии не подбирает другого сотрудника. Обычный task clone не превращает значения в связанную сводку.

## Один созвон — одна задача

1. **Add task → Shared activity**. Укажите название, секцию, дату события, организатора и участников; начало в UTC необязательно.
2. Выберите два **разных существующих duration-поля** проекта: Ordinary Plan duration field и Ordinary Actual duration field. При необходимости сначала создайте обычные колонки в таблице. Поля выбираются по идентичности, а не по словам Plan/Fact. Дополнительно можно связать single-select Work category field.
3. Задайте длительность события и состав **Call participants**. Это отдельный roster, не обычные Task collaborators. Организатор получает вклад только если включён в roster. Каждый текущий участник получает полную плановую длительность, а не её долю. Персональные исключения плановых минут в первом срезе отключены, чтобы не обходить блокировки обычного Plan-поля.
4. Добавьте Recording URL, Summary URL или текст Summary. Ссылки не загружают запись и не создают автоматическую расшифровку. Сохраните активность; добавление участника ещё не подтверждает, что он присутствовал.

Текущий план каждого активного участника следует текущему значению выбранного Plan-поля. Первоначальное предложение (`originalPlannedMinutes`) сохраняется отдельно и не переписывается текущим планом. Обычное изменение Fact-поля также не переписывает уже подтверждённое личное время.

### Подтвердить факт

Отредактируйте фактическую длительность в обычном выбранном поле задачи, затем откройте **Confirm attendance**, выберите нужных людей и подтвердите строки:

| Состояние | Личный факт |
| --- | --- |
| **Present — full duration** | Полная фактическая длительность события на момент подтверждения. |
| **Partial** | Явно введённые минуты от нуля до длительности события. |
| **Absent — zero minutes** | Подтверждённый ноль. |
| **Not confirmed** | Неизвестно, а не ноль; в отчёте показывается неполное покрытие. |

Для Present/Partial сначала нужен Fact. Отсутствие можно явно подтвердить нулём. Подтверждение сохраняет версии roster/длительности и категорию с её label/color. Смена текущих настроек или категории не переписывает эти записи. Коррекция, void, восстановление либо явная рекатегоризация требуют причины и создают новую неизменяемую версию истории. Удаление человека из текущего roster не стирает подтверждённое прошлое.

Права проверяются сервером и при повторе команды. Member с `time.write_self` подтверждает только себя; Owner/Admin с `time.write_others` могут записывать время других. Само звание Organizer таких прав не даёт. Настройка активности требует `task.edit`; общие шаблоны и их связи — `fields.manage` (Owner/Admin). Viewer читает доступные данные, но не подтверждает время и не меняет настройки.

## Увидеть личные часы в сводках и Reports

Для персональной секции задайте Person, **This person's work across this project** и показатель **Personal effort including shared participation**, указав нужное обычное Plan/Fact duration-поле. Это позволяет показать личные задачи и созвоны, которые лежат в другой секции. Для обычной суммы конкретной колонки оставьте Ordinary task values → Sum.

В **Reports** выберите **Calculation → Personal effort** и duration-поле. Для сравнения плана/факта отдельно задайте **Compare time as → Personal effort**; выбор источника сравнения не меняет автоматически операции остальных показателей. В workspace dashboard источники берутся из явно выбранных сохранённых отчётов. Можно оставить рядом обычный SUM для сопоставления.

Пример: личная задача 120 минут и общий созвон 60 минут с пятью подтверждёнными полными участниками. Обычный **SUM = 180 минут**: каждое значение задачи один раз. **Personal effort = 420 минут**: 120 + 5 × 60. Для каждого участника созвон даёт 60 минут; организатору дополнительно не добавляется ещё один вклад. Не складывайте SUM и Personal effort как две части одного итога.

Показываются число уникальных задач, число участий и coverage. Неподтверждённые записи остаются неизвестными; известный subtotal не объявляется полным итогом. Связанные размещения canonical task не добавляют повторные часы. Даты отчёта выбирают текущую когорту задач: это не журнал посещаемости по дням и не доказательство отработанного рабочего времени. Разбивка по типам использует настроенную категорию и сохранённые цвета; неполученная категория остаётся отдельным состоянием.

## Ограничения этого среза

- Для Personal effort **initial snapshot capture и query отключены**; автоматического backfill нет. Прежние task-value snapshots не переписываются. Текущее личное планирование, исходное предложение и история attendance не заменяют один другим разные исторические модели.
- Индивидуальные planned overrides отключены: только полная общая длительность Plan каждому человеку в roster, без обхода правил поля. Это не ограничивает фактическое Partial attendance или локальные display/capacity targets шаблона.
- Повторение общих активностей/автоматическое создание из календаря не реализованы. Старый native meeting engine сохраняет отдельный контракт; новый режим не преобразует его автоматически.
- Клонирование shared activity или содержащего её дерева/секции явно отклоняется; молчаливого превращения в обычную задачу или копирования факта нет. Настройки связанной сводки можно копировать отдельно от задач.
- Не создаются автоматические шаблоны, демонстрационные созвоны или преобразования существующих задач/данных. Поля, roster, связи и report sources задаются пользователем. Production/deploy в эту документационную задачу не входят.
- Одновременно допускается до 100 текущих участников активности, до 1 000 исторических участников; сверхполный scope не обрезается до «успешного» частичного итога. Изменения защищены текущими правами, версиями и идемпотентными командами.

Финальные общий build/global, согласованный PostgreSQL-прогон, native browser, main Auth/старые вкладки, локальная активация и production **НЕ ПРОВЕРЕНЫ** для этого среза.
