# Локальный импорт Asana через интерфейс

В списке **Projects** рядом с **New project** появился путь **Import from Asana**. Он использует тот же [повторяемый метод импорта](108-reusable-asana-import.md), что CLI и скилл: отдельной логики переноса данных для браузера нет.

Интерфейс принят и активирован локально 21 октября 2026 в **18:05:33.474 UTC** на `http://127.0.0.1:4310/app`; итоговая запись ниже отделяет private QA от непроверенных пользовательских сессий и production. Ранее принятый импорт 41-й/42-й недель и его ограничения остаются зафиксированы в [108](108-reusable-asana-import.md).

## Как импортировать проект

1. Войди через общий Auth как **владелец** нужного workspace и открой **Projects**.
2. Нажми **Import from Asana**. Выбери **Asana JSON export** и **Asana CSV export** одного и того же проекта. Лимит — **10 MiB на каждый файл**. Выбор файла сам по себе ничего не отправляет.
3. При необходимости раскрой **Advanced import options**. Обе опции по умолчанию выключены:
   - **Import milestones as ordinary tasks** разрешает представить milestone обычной задачей с сохранением исходного типа в provenance.
   - **Keep unresolved external dependencies as source metadata** сохраняет подписи внешних зависимостей, для которых в экспорте нет доступного ID. Новые связи по догадке не создаются.
4. Нажми **Check files**. Оба исходных файла отправятся локальному серверу для проверки и подготовки плана. Проект и задачи на этом шаге не создаются.
5. В предпросмотре проверь название проекта, число задач и секций, корневые задачи/подзадачи, завершённые задачи, новые/повторно используемые задачи, поля и предупреждения.
6. Нажми **Import project**. Пока запрос выполняется, окно остаётся открытым и показывает статус; повторный клик не запускает второй импорт. Закрытие окна не является отменой серверной операции.
7. После подтверждённого результата нажми **Open project**. Список проектов обновляется; ссылка учитывает короткий адрес workspace. Чтобы перенести следующий проект, нажми **Import another project**: файлы, дополнительные опции и результат сбросятся для нового выбора. Эта кнопка доступна также после распознавания уже импортированного проекта; при неизвестном результате применения она не появляется.

Если точная пара уже была успешно импортирована, предпросмотр показывает **Open project** сразу. Кнопки повторного импорта нет: открывается прежний проект. Поддерживается распознавание существующих обычных и прежних локальных журналов; при конфликте источников импорт останавливается для проверки оператором.

Интерфейс не требует выбирать неделю, задавать даты проекта или создавать отчёт. После переноса поля остаются обычными кастомными полями. Период проекта, отображение колонок и отчёты настраиваются отдельно обычными средствами приложения.

## Когда кнопка доступна

Кнопку видит только владелец workspace после положительного ответа capability endpoint. При 401, 403, 404 или отсутствии включённой возможности кнопка скрыта без предупреждающего toast и без повторных фоновых попыток запроса.

Сервер регистрирует этот маршрут только для **локального приложения с общим Auth и управляемой локальной базой Workloom**. Нужен настоящий авторизованный пользователь-владелец; fixture-аккаунт, член команды или администратор без роли owner не получают права импортировать через этот endpoint. Проверка владельца повторяется на сервере при проверке файлов и применении импорта; одного видимого UI недостаточно для доступа.

В hosted/production окружении маршрут не регистрируется, поэтому кнопки там нет. Это определяется серверной возможностью, а не `NODE_ENV` или флагом Vite: оптимизированная сборка локального приложения может показывать кнопку, если её локальный сервер разрешает импорт. Перенос локальной базы в production — отдельная задача.

## Если импорт не завершился

- **Файлы не прошли проверку:** убедись, что JSON и CSV относятся к одному проекту, и проверь дополнительные опции. Можно исправить выбор и повторить **Check files**; выбранные файлы сохраняются в открытой форме.
- **Нужны сопоставления:** сначала добавь или пригласи реальных участников в **Members**. Если исходные адреса отличаются либо нужна проверка типов полей, оператор должен подтвердить private mapping для общего метода. Имена людей, названия файлов или полей не дают разрешения угадывать соответствия.
- **Конфликт с существующим импортом или общей задачей:** не создавай новый журнал и не меняй namespace для обхода проверки. Вернись к исходной паре/опциям либо попроси локального оператора проверить конфликт. Уже существующие канонические данные не перезаписываются молча.
- **Ответ потерялся после Import:** результат мог сохраниться. Нажми **Retry the same import**. В этой форме повтор использует прежние upload ID и Idempotency-Key; JSON/CSV повторно не загружаются. После закрытия и повторного открытия окна на той же странице этот результат и путь повтора сохраняются. Автоматического повтора нет.
- **Другой импорт ещё работает:** дождись его завершения и повтори ту же операцию. Не запускай параллельные попытки для одного источника.
- **Сессия или права изменились:** войди владельцем и повтори проверку доступа. Поздний ответ старого пользователя не публикуется в контексте другого аккаунта.

Сам импорт возобновляемый, а не одна транзакция на весь проект. При сбое после части записей используется тот же обычный durable journal и source-project claim общего метода. После перезагрузки страницы или перезапуска приложения локальный оператор может продолжить исходный импорт; повторная загрузка точной пары также проверяет существующий журнал. Не удаляй `.local/imports/` для «исправления» ошибки и не подменяй архивы: это данные восстановления. Подробности — [Failure and resume](108-reusable-asana-import.md#failure-and-resume).

## Файлы и границы переноса

Браузер читает исходные байты файлов, включая UTF-8 BOM, и отправляет их только после **Check files**. Содержимое экспорта не записывается в `localStorage`/`sessionStorage`. Выбор и состояние окна удерживаются в памяти страницы. Локальный сервер сохраняет owner-private копии исходных файлов и метаданные загрузки под `.local/imports/browser-uploads/`; обычные архивы, mapping, журналы и claims общего метода также сохраняются. Не публикуй эти каталоги и не включай их в репозиторий.

В интерфейсе показываются безопасные объяснения ошибок, а не исходные серверные сообщения, пути файлов или содержимое payload. Имена проектов/полей и предупреждения предпросмотра отображаются как текст.

Импорт сохраняет только доступное в экспортах и в поддерживаемой модели. Полная история Asana, отсутствующие комментарии и вложения не восстанавливаются. Исходные даты/ссылки и дополнительная информация могут храниться как provenance, но не превращаются в выдуманную историю действий. Текущие часы не создают work logs, baseline исходной оценки, посещение созвонов или графики занятости.

Общие задачи повторно используются по исходному GID, а не по названию. Их статус и канонические данные общие, поля проекта сохраняются отдельно. Текущий блок **Linked tasks** показывает поля целевого проекта только для чтения. Проектные отчёты учитывают размещения, а workspace-отчёты сохраняют атрибуцию канонического домашнего проекта; подробные ограничения описаны в [108](108-reusable-asana-import.md#current-visible-limits).

Это UX-дефект, который одних функциональных кликов Playwright не выявили: перед кликом инструмент прокручивал содержимое. Финальная повторная приёмка проверила геометрию кнопок до кликов и автоматической прокрутки: действия целиком внутри viewport и диалога, scrollTop равен нулю. Первая попытка (2/2 функциональных сценария за 4,66 с) и её скриншот сохраняются как исторические доказательства, без подмены визуального результата.

Private compiled browser проверил настоящие HTTP-запросы к изолированному API: предпросмотр без создания проекта/задач, импорт двух синтетических задач и числового поля со значениями 0 и 3, открытие проекта, повтор той же пары без дублей, **Import another project** с очисткой формы и восстановление интерфейса после некорректного JSON. Тестовый Auth принадлежал этому private harness. После проверки private API остановлен, дочерняя база удалена. Эти действия не относятся к основной пользовательской базе.

Первичные bootstrap-сбои private QA сохранены: запуск HTTP-теста с неподходящим Vitest include завершился `No test files found` (exit 1); ранний backend typecheck не находил ещё не собранные локальные workspace-пакеты. В отдельной frontend-копии initial typecheck не находил не скопированный `scripts/localization-audit.ts`, а ранний localization audit отклонил три литеральных machine-error сообщения. После исправления harness и использования общего безопасного слоя ApiError повторные проверки прошли. Эти исходные сбои не помечены как PASS и не являются доказательством запуска пользовательского Auth.

Эти области частично пересекаются: числа не складываются в общее количество уникальных тестов. Ранее зафиксированный broad-web RED остаётся историческим; focused-проверки не означают новый зелёный полный web suite.

Проверены явный выбор двух файлов без автоматической отправки, сохранение исходных байтов, owner/capability gate, скрытая кнопка при 401/403/404, повтор предпросмотра, подтверждённое создание и ссылка с workspace slug, безопасный повтор неизвестного результата с тем же upload/key, переключение пользователя, ограничение размера, локализация предупреждений и **Import another project** после известного результата. Private PostgreSQL использует отдельную тестовую базу; импорт новых реальных Asana-данных в основную локальную базу не выполнялся в рамках этой проверки.

Основной авторизованный браузер заблокирован известной ошибкой инициализации инструмента. Настоящий provider Auth, main authenticated UI, actual old-tab interaction и production — **НЕ ПРОВЕРЕНЫ**. Изолированный браузер с собственным тестовым Auth не заменяет эти проверки. Предыдущая фактическая активация и импорт 41-й недели на checkpoint `9a32016` остаются историческими доказательствами [108](108-reusable-asana-import.md), а не результатом новой кнопки.
