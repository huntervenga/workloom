Используются **только синтетические локальные пользователи**, без входа реальных пользователей. Переключение тестовых участников проверяет роли. Оно не заменяет настоящий вход и приглашения команды. Временный нативный PostgreSQL 17 слушает только `127.0.0.1:55432`; существующий `.env` уже связан с ним. Не заменять `.env` примером Docker на порту 54329, не останавливать чужие PostgreSQL и не очищать демо-данные или БД ради запуска. Учётные данные в Markdown не копируются.

### Если процессы уже работают

Открыть приложение и проверить готовность сервера; второй API на порту 4310 не запускать. Перед рестартом проверить владельца текущего процесса и [состояние прогона](12-active-run.md): идентификаторы процессов меняются при проверках. Остановить только свой API или клиент через его терминал либо штатным сигналом SIGTERM, дождаться выхода, затем запускать заново. После перезапуска API старый подписанный курсор списка может получить ответ 400 — перезагрузить соответствующий список. Не повторять неизвестную запись с новым ключом: использовать исходную отправку.

### Если нужно запустить остановленный проект

Node.js 24.19.0 закреплён в `.node-version`/`.nvmrc`; команды выполняются из корня:

```sh
cd /Volumes/PavelData/ai/workloom
node --version
npm run dev
```

На этом компьютере Node.js 24 доступен также в `/Users/pavelignatov/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin`. Сначала включить его в PATH, если командная оболочка показывает другую версию. Зависимости уже установлены; для чистой копии — `npm ci`, полный порядок установки и создания новой БД находится в [README](../README.md#локальный-запуск). Если существующий PostgreSQL остановлен, сначала восстановить именно согласованный локальный кластер; не создавать поверх него новый.

Для проверки собранной SPA вместо Vite, после остановки прежнего API:

```sh
npm run build
NODE_ENV=production npm start
```

`NODE_ENV=production` здесь означает сборку; `APP_ENV=local`/`AUTH_MODE=dev` остаются локальной границей. Это локальный запуск, а не публикация. После новых миграций отдельным согласованным шагом выполнить `npm run db:migrate` до старта новой версии; приложение при старте само схему БД не меняет.

Фоновый обработчик запускается отдельно, `npm run dev` его не включает. После явной подготовки схем приложения и очереди — `npm run db:queue:migrate`, затем `npm run start --workspace @workloom/worker`. Проверять `worker.health`/`worker.health_queue`; останавливать штатным сигналом SIGTERM. Не включать обработчик посреди согласованной демонстрации или проверки без координации. Подробности: [worker README](../apps/worker/README.md).

Сохранённый серверный отчёт: **план — 41 ч, факт — 40 ч 45 мин**. Фактические трудозатраты ниже плана на 15 мин. **Фактические трудозатраты встречи — 3 ч 30 мин** суммарно по участникам. Категории факта: «Разработка» — 24 ч 30 мин (60,12 %), «Исследование» — 12 ч (29,45 %), «Командная работа» — 4 ч 15 мин (10,43 %). Это результаты синтетического примера, а не реальные часы команды и не доказательство полноты будущего учёта.

Проход можно выполнить чтением. Новые записи безопаснее пробовать в отдельном синтетическом проекте, сохраняя этот контрольный пример.

1. **Таблица, 1–2 минуты.** Открыть задачу и участников, колонку с историей, текущую оценку. Общая оценка относится к одному пакету работы. Подзадача-детализация разделяет пакет родителя, а `added_scope` создаёт отдельный. Один пакет учитывается один раз независимо от числа подзадач и людей.
2. **Неделя и план/факт, 2 минуты.** Явно выбрать период и человека. Различить текущий бюджет, личный недельный план и исходный зафиксированный план. Открыть сохранённый отчёт: он закрепляет версии, а не пересчитывает прошлое из текущей таблицы. Подтверждённый ноль, отсутствие записи и аннулированный факт различаются.
3. **Общая встреча, 1–2 минуты.** Открыть одну задачу встречи: план предлагается отдельно, фактическое присутствие — отдельная атомарная команда. Приглашение и список участников сами не начисляют часы. Полное или частичное присутствие, отсутствие и неизвестное состояние различаются. Сохранение ссылки или длительности само не переписывает факт.
4. **Зависимости и даты, 1–2 минуты.** Переключить таблицу в граф и Gantt. Блокирующие задачи определяются сервером; личное положение узлов не двигает задачи. Диапазон календарных дат не выводится из оценки в часах. Изменение дат сначала показывает предварительный просмотр. Наложение исходного плана сохраняет неизвестные старые даты неизвестными.
5. **Типы работы и импорт, 1–2 минуты.** Открыть сохранённый отчёт по категориям: «Без категории» входит в знаменатель; теги могут пересекаться. В импорте посмотреть исходник, сопоставление колонок и сверку результата. Исходные HoursEst/HoursFact сохраняются с явными единицами в выбранных колонках, не становятся исходной оценкой или недельный факт автоматически.
6. **Локальный MCP, принят P5b.** Пространство → «Интеграции»: личные разрешения, срок и отзыв. Секрет виден один раз в памяти браузера, сервер хранит хеш и метаданные. Запускать собранный main напрямую, без служебного вывода npm; точная [конфигурация клиента](../apps/mcp/README.md). При неизвестном результате записи повторять строго исходный вызов с тем же `operationKey`. Текущее участие и отзыв ключа проверяются и перед возвратом сохранённого результата.

## Что готово и где граница

| Доступно локально | Ограничение |
| --- | --- |
| Таблица, задачи/подзадачи, роли тестовых участников, типизированные колонки и история | Задачи видны пространству; нет полноценного приватного доступа, сохранённых представлений, массовой вставки и общей истории всех встроенных полей |
| Личные недельные планы, неизменяемая фиксация, ручной факт, категории и сохранённые отчёты | Нет полного процесса закрытия, корректировок и переносов, дневного учёта, обязательного факта при Done и общего конструктора отчётов |
| Разовые встречи и конечные серии, присутствие, версии/исключения и отдельный обработчик | Не внешний календарь, не рассылка приглашений, не произвольные бесконечные повторы; перенос между периодами ограничен |
| Зависимости, предупреждение или запрет смены статуса, личный граф, ручные даты и ограниченный Gantt | Нет автопланирования и каскадного сдвига, перетаскивания сроков, ресурсного календаря и исторической топологии |
| CSV до 50 строк задач, пять скалярных типов, явные существующие ссылки, предварительный просмотр, атомарное применение и сверка | Нет полного переноса Asana через JSON/API, комментариев, вложений и приватных прав; исходная история не придумывается |
| Принятый ограниченный MCP A+B: 7 чтений и 2 защищённые записи, собственные ключи | Только локальные stdio и loopback, без удалённого MCP/OAuth и без заявления полного P5.8 |

Shared Auth ещё не подключён; создание реальных пространств, отправка и принятие приглашений, отзыв настоящих сессий не реализованы. Railway — [план эксплуатации](08-railway-and-operations.md), а не созданные промышленные сервисы. Локальные миграции и health-проверки не заменяют тестовую площадку, резервное копирование и восстановление, обновление старой вкладки и разрешённую публикацию. Внешние Google/Microsoft календари — [будущее подключение только на чтение по выбору участника](10-calendar-integration.md), не зависимость текущего пилота.
